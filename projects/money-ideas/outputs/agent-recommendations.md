# 필요한 에이전트 추천 (idea-planner 작성)

> 기준: `VISION.md` — 아이디어를 **가치 확인 → 1~10단계 자동화 → 판매**까지 끌고 가려면 어떤 역할이 비어 있나.

## 흐름
```
idea-planner(발굴·브리핑) → market-validator(돈 낼 사람 확인) → automation-architect(1~10 자동화 설계)
→ developer(기존) → launch-marketer(판매 채널·홍보) → reviewer(기존) → 사용자
                              ↘ revenue-tracker(매출·비용 추적, 나중)
```

## 이미 있는 에이전트 재활용
| 에이전트 | 이 프로젝트에서 하는 일 |
|---|---|
| researcher | 점심 심층 조사가 커질 때 대신 맡김 |
| planner | 검증 통과한 아이디어의 spec·roadmap |
| developer | MVP·자동화 스크립트·랜딩페이지 코드 |
| content-writer | 판매 페이지 문구, 홍보 글 |
| reviewer | 사용자 전달 전 검수 |

## 새로 만들 후보
| 순위 | 이름 | 하는 일 | 왜 필요한가 | 크레딧 |
|---|---|---|---|---|
| 1 (추천) | **automation-architect** | 아이디어의 실행 단계를 1~10으로 쪼개고, 단계별로 "클로드 / 스크립트 / 예약 작업 / 사람"을 배정. 필요한 API·커넥터·비용 표 작성 | VISION의 핵심(시스템화·자동화)을 전담. 다른 프로젝트(쇼츠·업로드·입찰)에도 그대로 재활용 가능 | 적음 |
| 2 (추천) | **market-validator** | 돈 낼 사람이 있는지 확인: 경쟁사 가격, 고객 불만, 사전 신청 랜딩페이지·설문 설계, "검증 통과/탈락" 판정 | 만들고 나서 안 쓰는 일(다이어리 사례)을 막음. 개발 전에 걸러서 사용량 절약 | 적음 |
| 3 | **launch-marketer** | 판매 채널 선택(크몽·스마트스토어·자체 사이트 등), 가격 정책, 출시 체크리스트, 홍보 일정 | 만든 것을 실제로 "파는" 단계 담당 | 보통 |
| 4 | **revenue-tracker** | 매출·비용(클로드 사용량 포함)·지표를 구글 시트에 기록하고 주간 리포트 | 돈이 되는지 숫자로 판단. 첫 상품 출시 후에 필요 | 적음 (나중) |

## 선택지
1. **(추천) 1·2번만 지금 만들기** — 검증·자동화 설계까지가 지금 단계. 3·4번은 첫 아이디어가 "진행"이 되면.
2. 1~4번 전부 지금 만들기
3. 1번(automation-architect)만 — 우선 기존 프로젝트를 자동화 관점으로 재정리
4. 아직 안 만들고 브리핑 며칠 받아본 뒤 결정

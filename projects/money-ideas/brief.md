# 프로젝트: 수익화 아이디어 기획 (money-ideas)

## 목표
- `VISION.md`의 원칙대로 **돈을 받고 팔 수 있고, 시스템화·자동화가 가능한** 아이디어를 찾는다.
- 하루 3번(아침·점심·저녁) 리서치 결과를 알림으로 받고, 선택지를 고르거나 피드백한다.
- 고른 아이디어는 검증 → 자동화 설계 → 개발 → 판매까지 이어간다.

## 결과물 형태
- `outputs/briefings/YYYY-MM-DD-{am,noon,pm}.md` — 매 회차 브리핑
- `outputs/idea-pool.md` — 지금까지 나온 아이디어 전체와 점수·상태
- `outputs/feedback.md` — 사용자의 선택·피드백 누적
- `outputs/agent-recommendations.md` — 이 프로젝트에 필요한 에이전트 추천
- `outputs/connectors.md` — 추천 커넥터

## 담당 에이전트
- `idea-planner` (주담당: 리서치 + 브리핑 + 선택지)
- 이후: `agent-recommendations.md`에서 사용자가 고른 에이전트들 → `reviewer`

## 필요한 스킬
- `idea-briefing` — 회차별 브리핑 절차와 형식
- `idea-scoring` — 아이디어 점수 매기는 기준(VISION 기준표)
- 공통: `handoff`, `request-review`, `style-guide`, 깊은 조사는 `anthropic-skills:deep-research`

## 하루 일정 (예약 작업, 한국 시간)
| 시간 | 회차 | 하는 일 |
|---|---|---|
| 07:52 | 아침 | 새 아이디어 3개 발굴(트렌드·해외 사례·국내 수요) |
| 12:22 | 점심 | 사용자가 고른(또는 점수 1위) 아이디어 1개 심층 조사: 경쟁·가격·자동화 단계 |
| 20:52 | 저녁 | 하루 정리 + 내일 방향 선택지 + 피드백 질문 |

## 제약 / 참고
- 크레딧 절약: 회차당 웹검색 5~8회 이내, 브리핑은 휴대폰에서 1~2분 안에 읽히게.
- 게임처럼 개발 사용량이 큰 아이디어는 점수에서 감점.
- 출처 없는 숫자는 쓰지 않는다.

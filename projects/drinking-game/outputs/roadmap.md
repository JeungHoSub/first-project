# 술게임 — 로드맵 (초안 v0.1)

날짜 대신 단계 순서로 관리한다. 기본 가정: 웹앱, 게임 3~5개, 수익 미정. MVP는 1~2주 안에 돌아가는 것을 목표로 한다.

| 단계 | 이름 | 담당 에이전트 | 할 일 | 산출물 | 완료 기준 |
|---|---|---|---|---|---|
| 1 | 기획 | planner | 형태·MVP 게임 후보·안전 요구사항 정리, 확인 항목 정리 | `outputs/spec.md`, `outputs/roadmap.md` | 사용자가 spec을 읽고 확인 항목(형태·게임 수·수익)에 답함 |
| 2 | 게임 설계 | game-designer | 게임별 규칙(3문장 이내), 카드·벌칙 콘텐츠(음주/비음주 쌍), 카드 JSON 스키마 | `outputs/games.md`, `outputs/cards/*.json` | 게임당 규칙이 명확, 모든 벌칙 카드가 두 모드 문구 보유, 과음 유도 표현 0건 |
| 2.5 | 1차 검수 | reviewer | 규칙 명확성, 안전 문구, 저작권(기존 게임 복제 여부) 점검 | `outputs/review-1.md` | 지적사항 반영 완료 |
| 3 | 프로토타입 | developer | 부품 먼저: 플레이어 입력·카드 뽑기·룰렛·타이머. 게임 1~2개 연결 | `outputs/prototype/` (실행 가능) | 폰 브라우저에서 첫 게임을 끝까지 플레이 가능 |
| 4 | MVP | developer → reviewer | 나머지 게임 연결, 모드 선택, 성인 확인·안내 문구, 오프라인(PWA), 정적 호스팅 배포 | 배포 URL, `outputs/mvp/`, 사용 안내 | 아래 MVP 체크리스트 통과, reviewer 통과 후 `review/QUEUE.md` 등록 |
| 5 | 피드백 | 총괄 + planner | 사용자·지인 실사용 후 피드백 수집, 우선순위 정리, 학습된 선호는 style-guide에 추가 | `outputs/feedback.md` | 개선 항목이 우선순위와 함께 정리됨 |
| 6 | 확장 | planner → game-designer → developer | 게임·카드 추가, 카드 직접 입력, 인쇄용 카드·콘텐츠 재활용, 수익 방식 결정 시 팩 분리 | 업데이트된 spec/카드 JSON, 필요 시 별도 기획 | 사용자가 확장 범위를 선택해 승인 |

## MVP 체크리스트 (4단계 완료 기준)

- 게임 3~5개 플레이 가능
- 음주/비음주 모드 동등 동작, "패스" 가능
- 성인 확인 문구, 음주 강요 금지·운전 금지 안내 노출
- 카드 데이터가 JSON으로 분리됨(코드 수정 없이 카드 추가 가능)
- 모바일(iOS Safari, Android Chrome) 동작
- 서버·계정·개인정보 수집 없음

## 단계별 위험·비용

| 단계 | 비용 | 법적·품질 위험 | 대응 |
|---|---|---|---|
| 기획~설계 | 없음 (AI 사용량만) | 기존 게임 규칙·문구 복제 | 자체 문구로 재작성, reviewer 점검 |
| 프로토타입 | 없음 | 없음 | — |
| MVP 배포 | 정적 호스팅 무료 플랜 예상(약관 확인), 도메인은 선택 | 미성년자 노출, 과음 유도 | 안내 문구, 비음주 우선 설계 |
| 확장(광고·결제·앱 출시) | 미정 | 광고·스토어 주류 정책(미확인), 개인정보, 결제 약관 | 해당 단계 시작 전 정책을 직접 조사 후 결정 |

## 선행 조건

| 필요한 것 | 시점 | 비고 |
|---|---|---|
| 사용자의 확인 항목 답변 | 2단계 시작 전 | 안 오면 추천안(웹앱·3~5개·수익 미정)으로 진행 |
| 카드 JSON 스키마 합의 | 2단계 중 | game-designer와 developer가 함께 정함 |
| 호스팅 선택 | 4단계 전 | developer가 선택지 제시 |

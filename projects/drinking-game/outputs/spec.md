# 술게임 — 기획 명세 (초안 v0.1)

작성: planner / 2026-11-12
기본 가정: brief "확인 필요"의 추천안(형태 A, 게임 수 A). 수익은 C(미정).

## 1. 목표 / 대상 / 사용 상황

| 항목 | 내용 |
|---|---|
| 목표 | 모임 자리에서 폰 하나만 있으면 바로 시작하는 게임 모음 웹앱. 설치·가입 없이 링크 열고 3탭 안에 시작 |
| 대상 사용자 | 성인(만 19세 이상) 친구·동료 모임 3~10명. 술을 안 마시는 사람도 같이 끼는 자리 포함 |
| 사용 상황 | 술집·집들이·MT 등 시끄럽고 어두운 곳. 한 손 조작, 글씨 크게, 음량 없이도 진행 가능 |
| 성공 기준(MVP) | 처음 보는 사람이 설명 없이 첫 게임을 시작할 수 있음 |

## 2. MVP 게임 후보 (규칙 세부는 game-designer)

| # | 후보 이름 | 한 줄 설명 | 필요한 앱 기능 | 선정 이유 |
|---|---|---|---|---|
| 1 | 벌칙 룰렛 | 돌려서 걸린 사람/벌칙을 정함 | 룰렛(가중치 없음), 플레이어 목록 | 가장 단순, 어떤 모임에도 맞음 |
| 2 | 미션 카드 뽑기 | 카드를 한 장 뽑아 지목된 사람이 미션 수행 | 카드 덱, 셔플, 플레이어 순서 | 콘텐츠(카드)만 늘리면 확장됨 |
| 3 | 진실 혹은 도전 | 질문에 답하거나 도전을 수행 | 카드 덱(2종), 선택 버튼 | 대화 유도, 비음주 모드 적합 |
| 4 | 폭탄 돌리기 | 타이머가 끝나기 전에 폰을 넘김, 터진 사람이 벌칙 | 랜덤 타이머(숨김), 효과음/진동 | 폰 하나로 돌려쓰는 형태에 딱 맞음 |
| 5 | 초성/주제 게임 | 제시된 초성·주제에 맞는 단어를 차례로 말함 | 랜덤 제시어, 턴 타이머 | 규칙이 쉽고 준비물 없음 |

- 5개를 상한으로 보고, 일정이 빠듯하면 1·2·4만 MVP로 줄인다.
- 3개 게임이 "카드 덱 + 룰렛 + 타이머" 3가지 부품을 공유하도록 후보를 골랐다. 부품이 같으면 게임 추가 비용이 낮다.

## 3. 공통 기능

| 기능 | MVP | 설명 |
|---|---|---|
| 플레이어 이름 입력 | O | 2~10명, 닉네임만. 서버 저장 없음(기기 내 임시 저장) |
| 벌칙 모드 선택 | O | 음주 / 비음주. 시작 화면에서 선택, 게임 중 변경 가능 |
| 게임 선택 화면 | O | 게임 카드 목록 |
| 성인 확인 / 이용 안내 | O | 최초 진입 시 1회 (4절 참조) |
| 카드·벌칙 데이터 로딩 | O | JSON에서 읽음 (6절 참조) |
| 오프라인 동작 | 가능하면 | 설치 없이 열고, 한 번 연 뒤에는 네트워크 없이도 동작(PWA 캐시) |
| 사운드/진동 | O | 끌 수 있어야 함 |
| 카드 직접 추가 | 이후 | 모임 전용 벌칙 입력 |
| 결과 공유 | 이후 | |

### 벌칙 모드 원칙 (비음주도 1급)
- 모든 벌칙 카드는 음주용 문구와 비음주용 문구를 **쌍으로** 가진다. 한쪽만 있는 카드는 배포하지 않는다.
- 비음주 모드는 "대체 옵션"이 아니라 같은 화면·같은 재미 수준을 목표로 한다(행동 미션, 말하기, 포인트 등).
- 음주 모드에서도 "마시기"만 있지 않도록 한다. 어느 모드든 "패스" 버튼을 둔다.

## 4. 안전·정책 요구사항

| 항목 | 요구사항 |
|---|---|
| 과음 유도 표현 금지 | "원샷", "취할 때까지", "짬뽕", 연속 음주 강제 등 과음을 부추기는 문구를 카드·UI에 쓰지 않는다. 음주 모드 벌칙은 "한 모금" 수준의 상한을 둔다(상한 기준은 game-designer가 정하고 reviewer가 점검) |
| 음주 강요 금지 안내 | 시작 화면·벌칙 화면에 "마시기 싫으면 언제든 패스하거나 비음주 모드로 바꿀 수 있어요" 문구 상시 노출 |
| 성인 확인 / 미성년자 제한 | 최초 진입 시 "만 19세 이상만 음주 모드를 쓸 수 있어요" 확인 문구와 버튼. 미동의·미확인 시 비음주 모드만 사용 가능. 단순 자기 선언 방식이며 실제 연령 인증은 아님을 인지 |
| 건강·운전 안내 | "음주 후 운전 금지, 건강 이상 시 즉시 중단" 문구 포함 |
| 개인정보 | MVP는 계정·서버 저장 없음. 플레이어 이름은 기기 안에서만 사용. 분석 도구를 붙이면 그때 개인정보 처리방침 필요 |
| 저작권 | 기존 상용 술게임·TV 프로그램의 고유 규칙명·문구·이미지 복사 금지. 전래 규칙(초성 게임 등)은 자체 문구로 재작성. 카드 문구는 자체 창작 |
| 앱스토어 주류 정책 | 웹앱이라 MVP에서는 해당 없음으로 본다. **앱 출시(스토어 등록) 시점에 각 스토어의 주류·연령 관련 정책을 직접 확인해야 한다. 현재 확인된 바 없음** |
| 광고 정책 | 광고를 붙일 경우 광고 플랫폼의 주류 관련 콘텐츠 정책 확인 필요(미확인) |

## 5. 기술 선택안

| 항목 | 추천 | 이유 / 대안 |
|---|---|---|
| 형태 | 정적 웹앱(PWA) | 설치 불필요, 링크/QR로 공유, 오프라인 가능 |
| 프런트 | 가벼운 프레임워크 또는 순수 HTML/JS (developer가 결정) | 번들 작게, 모바일 로딩 빠르게 |
| 데이터 | `cards/*.json` 정적 파일 | 서버·DB 불필요 |
| 호스팅 | 정적 호스팅(무료 플랜 범위) | 서버 코드 없음 |

## 6. 재활용 구조 (하나 만들어 여러 곳에)

카드 콘텐츠를 앱 코드와 분리해 **단일 원본 JSON**으로 관리한다.

| 원본 | 재사용처 |
|---|---|
| `cards/*.json` (게임, 모드별 문구, 태그) | 웹앱 / 인쇄용 카드(PDF 변환) / 유튜브·쇼츠 콘텐츠 대본 / 이후 유료팩 |

- 카드 필드 예시(항목명만): id, 게임, 본문, 음주 벌칙, 비음주 벌칙, 강도, 팩 이름, 버전. 최종 스키마는 game-designer와 developer가 정한다.
- "팩 이름" 필드가 있으면 나중에 무료팩/유료팩/광고 팩을 데이터만으로 나눌 수 있다.
- 쇼츠 프로젝트(`shorts-auto`)와 카드 문구·영상 소재를 공유할 수 있는지는 이후 검토.

## 7. 비용 · 법적 위험 (한 칸 요약)

| 구분 | 내용 |
|---|---|
| 비용 | MVP는 사실상 0원 수준 예상: 정적 호스팅 무료 플랜 + 서버 없음 + API 호출 없음. 도메인 구입 시 연 단위 소액. 카드 문구를 AI로 생성하면 토큰 비용이 약간 발생하나 일회성 |
| 법적 위험 | 과음 유도·미성년자 노출(4절 문구로 완화), 기존 게임 규칙·문구 복제(저작권), 광고/스토어 진출 시 주류 정책(미확인), 분석 도구 도입 시 개인정보. 최종 법률 판단은 사용자가 필요 시 전문가에게 확인 |

## 9. 범위 밖 (Out of scope)

- 네이티브 앱 스토어 출시, 계정·로그인, 서버 저장, 온라인 멀티플레이(각자 폰 접속)
- 실시간 채팅, 주류 구매·배달 연계, 음주량 측정·기록, 연령 실인증
- 결제·광고 실제 연동(구조만 대비), 다국어
- 인쇄용 카드·영상 콘텐츠 제작(데이터 구조만 호환시킴)

## 10. 확인 항목별 "다른 선택지일 때 달라지는 점"

### 1) 형태 (현재 가정: A 웹앱)
- brief의 "추천" 표시는 A(웹앱) 뒤에 붙어 있다. 이 문서는 추천안인 A를 가정함.
- B(인쇄/유튜브): developer 단계 삭제, 카드 데이터 → 디자인/영상 제작이 중심. media-producer가 필요하고 저작권(영상) 점검 추가.
- C(둘 다): 카드 JSON 원본이 핵심이 되어 6절 구조가 그대로 이득. 일정은 약 1.5~2배 예상.

### 2) 첫 게임 수 (현재 가정: A 3~5개)
- B(10개 이상): game-designer 작업량이 크게 늘고, 규칙 검수(reviewer) 시간 증가. 카드·룰렛·타이머 부품 외에 새 UI가 필요한 게임이 섞임.
- MVP 공개가 늦어져 피드백 단계가 뒤로 밀림. 권장: 5개로 출시 후 피드백 보고 확장.

### 3) 수익 (현재 가정: C 미정)
- A(무료/광고): 광고 SDK·정책 확인, 개인정보 처리방침, 로딩 속도 저하 대비 필요. 광고 플랫폼의 주류 콘텐츠 정책 미확인.
- B(유료 카드팩): 결제 연동(웹 결제), 팩 잠금 구조, 환불·약관 필요. 카드 JSON의 "팩 이름" 필드가 바로 쓰임.
- C(미정): MVP는 무료 공개, 데이터 구조만 팩 분리 가능하게 둔다. 지금은 추가 비용 없음.

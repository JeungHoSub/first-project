# 쇼츠 편집 + 자동 업로드 로드맵 (초안)

- 작성: planner / 2026-11-12
- 기준 문서: `spec.md` (절 번호는 spec 기준). "기본 가정" = 유튜브만, 편집 자동 + 업로드 전 사람 승인, 프로젝트별 채널, 비공개 업로드 후 사람이 공개.
- 기간은 "집중해서 일한다면"의 대략치다. 사용자 응답이 늦으면 늘어난다.

## 한눈에 보기

| 단계 | 이름 | 기간 | 목표 |
|---|---|---|---|
| 0 | 준비 | 며칠 (사용자 작업 포함) | 계정·API·원본 1개·표준 형식 준비 |

## 0단계: 준비

### 사용자가 할 일
1. **채널 결정** — spec 14절 3번(추천: 프로젝트별 각 채널). 시범 대상 프로젝트 하나 고르기(14절 4번).
2. **본편 영상이 있는 채널 확인** — 쇼츠를 올릴 채널에 본편이 이미 있거나 곧 올릴 예정이어야 함(본편 공개 전엔 쇼츠 업로드 안 함).
3. **Google Cloud 설정** (`youtube-upload` 스킬 "자동 업로드 준비"와 동일)
   1. Google Cloud 프로젝트 생성, YouTube Data API v3 사용 설정
   2. OAuth 동의 화면 설정(테스트 사용자에 본인 계정 추가)
   3. OAuth 클라이언트(데스크톱 앱) 생성 → `client_secret.json` 내려받기 (저장소에 올리지 않고 `projects/shared/uploader/secrets/`에 둠)
   4. Cloud Console의 **할당량 화면 캡처/수치 메모** (spec 13절 1번 실측용)
4. 원본 영상 파일 준비: 시범 프로젝트의 완성 영상 1개를 사용자 PC(또는 접근 가능한 곳)에 두기.
5. (선택) 세션 네트워크에서 공식 문서 도메인(support.google.com, developers.google.com 등) 허용 → researcher가 공식 원문 재확인.

### 에이전트가 할 일
| 담당 | 할 일 |
|---|---|
| 총괄 | `.gitignore`에 영상·비밀 파일·work/ 제외 추가, 사용자 답변을 brief에 반영 |
| planner | spec 기본 가정과 사용자 답변 대조·수정 |
| researcher | (선택) 공식 문서 허용 시 spec 13절 항목 재조사 |

### 완료 기준
- 사용자 확인 필요 1~3번 답변이 brief에 반영됨.
- `client_secret.json`이 `secrets/`에 있고 git에 올라가지 않는 것이 확인됨.
- 시범 원본 영상 1개의 위치가 정해지고, 그 프로젝트에 `rights.md`가 있음(없으면 먼저 작성: 해당 프로젝트 담당).

### 선행 조건
- 없음 (첫 단계). 시범 프로젝트의 완성 영상이 아직 없으면 그 프로젝트 제작이 먼저다.

## 1단계: MVP — 쇼츠 1편, 수동 승인

### 할 일과 담당
| # | 할 일 | 담당 | 산출물 |
|---|---|---|---|
| 1-1 | 표준 `shorts-candidates.md` 형식 확정, 시범 프로젝트에 후보 1~3개 작성 | planner + 시범 프로젝트 담당 | `projects/<시범>/outputs/shorts-candidates.md` |
| 1-2 | 후보 권리 확인(승계) | reviewer (copyright-check) | `plans/<쇼츠ID>/rights-check.md` |
| 1-3 | 후보 1개 선정, 편집 계획 작성 | media-producer | `plans/<쇼츠ID>/edit-plan.yaml` |
| 1-4 | ffmpeg 렌더 스크립트: 자르기 → 9:16(blur-bg/crop-center) → 자막 번인 → 썸네일 | developer(스크립트) + media-producer(품질 확인) | `renders/<쇼츠ID>/short.mp4`, `thumb.jpg`, `subs.srt` |
| 1-5 | 제목·설명·태그 작성(변화 주기 반영, 본편 제목 텍스트 포함) | content-writer | `renders/<쇼츠ID>/metadata.yaml` |
| 1-6 | 1차 검수 | reviewer | `renders/<쇼츠ID>/review.md` |
| 1-7 | QUEUE 항목 추가, 사용자 승인 | 총괄 → 사용자 | `approval.yaml` |
| 1-8 | 업로더 최소판(`projects/shared/uploader/`): auth, upload(비공개), dry-run, upload-log.csv, 중복 방지, 재시도, 승인 확인 | developer | 모듈, `README.md` |
| 1-9 | **할당량·비공개 고정 실측** (spec 13절 1, 2, 3, 5, 7번) 후 결과를 spec·`youtube-upload` 스킬에 반영 요청 | developer → 총괄 | 실측 메모(`outputs/measurements.md`) |
| 1-10 | 비공개 업로드 → 사용자가 Studio에서 확인·본편 연결·공개 | developer → 사용자 | 로그 줄(`uploaded`, `made_public`) |
| 1-11 | 회고: 걸린 시간, 수동으로 한 것 목록, 문제점 | planner | `log.md` 항목(총괄 기록) |

### 진행 순서 메모
- 1-1~1-3과 1-8(업로더)은 병행 가능. 업로드(1-10) 전에 `--dry-run`으로 전체 검증.
- 업로더 최소판은 **YouTube만**, CLI 한 개 명령(`upload`)과 dry-run이 있으면 충분.

### 완료 기준
- 쇼츠 1편이 사용자 승인 후 채널에 올라가 Studio에서 공개 상태가 됨.
- 그 쇼츠가 Shorts로 분류됨(세로·3분 이하 규칙 실제 확인).
- `upload-log.csv`에 pending → uploaded → made_public 이력이 남음.
- 같은 후보를 다시 올리려 하면 중복으로 거부됨(테스트로 확인).
- 승인 없이는 업로드가 거부됨(테스트로 확인).
- `client_secret.json`/토큰이 커밋 이력에 없음.
- 13절 실측 항목 중 1, 2, 3번에 답이 기록됨.
- 사용자가 "이 정도면 계속 쓸 만하다"고 확인.

### 선행 조건
- 0단계 완료. ffmpeg·Python 사용 가능한 환경.

## 2단계: 반자동

### 할 일과 담당
| # | 할 일 | 담당 | 산출물 |
|---|---|---|---|
| 2-1 | scan 스크립트: 모든 프로젝트의 `shorts-candidates.md`를 읽고 형식 검증 + `candidates-index.csv` 생성 | developer | scan 스크립트, 인덱스 |
| 2-2 | 다른 프로젝트(book-podcast, music-video-upload, claude-lecture)가 영상 완성 때 `shorts-candidates.md`를 남기도록 각 프로젝트 담당에게 안내 | 총괄 + 각 프로젝트 담당 | 각 프로젝트 후보 파일 |
| 2-3 | 편집 계획 일괄 생성(후보 N개 → 쇼츠 N개), 짜깁기(montage) 지원 | media-producer + developer | edit-plan 여러 개 |
| 2-4 | 배치 렌더 + 변화 주기 점검(구간 겹침, 제목·hook 반복 검사) | developer + reviewer | 렌더 + `review.md` |
| 2-5 | 메타데이터 일괄 작성(매번 새 문장) | content-writer | `metadata.yaml`들 |
| 2-6 | 샘플 검수 → 사용자 승인 후 **배치 단위** 업로드 (brief 5번 "샘플 검수 → 승인 후 일괄") | reviewer → 사용자 → developer | QUEUE 배치 항목 |
| 2-7 | 업로더 보강: 하루·주간 상한, 할당량 상태(`status`), 설정 파일, 다른 프로젝트 호출 예시(README) | developer | 보강된 모듈 |
| 2-8 | music-video-upload·book-podcast가 업로더로 본편 1편씩 올려 보기 | developer + 각 프로젝트 담당 | 로그에 다른 `project` 값 |
| 2-9 | 사용자의 Studio 수동 작업(본편 연결·공개)이 부담인지 점검하고, 자동화 가능 여부 재조사 | researcher | 조사 메모 |
| 2-10 | 게임 프로젝트 영상(매직고스톱·술게임)은 별도 법적 검토(사행성·음주 표현) 후 포함 여부 결정 | researcher + reviewer + 사용자 | 결정 기록 |

### 완료 기준
- 2개 이상 프로젝트에서 온 후보로 쇼츠 5편 이상을 배치로 올림(비공개 → 공개).
- 수집은 자동, 승인은 배치 1회로 처리 가능.
- 변화 주기 점검(구간·제목·hook 반복 없음)이 reviewer 체크 목록에 들어가 있음.
- 다른 프로젝트 1곳 이상이 공유 업로더를 실제로 사용.
- 한 달 정도 운영 후 수익화·노출 불이익 징후 점검(사용자 확인).

### 선행 조건
- 1단계 완료. 시범 외 프로젝트 중 최소 1곳에 완성 영상 + rights.md + 채널이 있음.

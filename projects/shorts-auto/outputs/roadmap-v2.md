# 로드맵 v2 (v1 `roadmap.md`의 변경분)

- 작성: planner / 2026-11-12. v1 roadmap.md는 그대로 두고, `spec-v2.md` 반영으로 달라진 부분만 적는다. 적지 않은 것은 v1과 같다.
- 기본 가정: 후보·계획·메타는 클라우드, 렌더·업로드는 사용자 PC.

## 0단계 준비 (추가·변경)
사용자가 할 일 추가:
1. **PC 환경 준비**: Python 3.11+, ffmpeg, git 설치. 저장소를 PC로 받기(`git pull` 가능하게).
2. **원본 폴더 정하기**: 환경변수 `SHORTS_SRC_ROOT` 지정, 시범 영상 1개 넣기.
3. Google Cloud 설정(v1과 같음) + OAuth 동의 화면이 "테스트"인지 "프로덕션"인지 기록. **토큰 만료 실측**(spec-v2 12절 8번): 로그인 후 일주일 안팎에 자동 재로그인이 필요한지 확인.
4. `client_secret.json`은 PC의 `projects/shared/uploader/secrets/`에만 둔다.

총괄: `.gitignore`에 `state/`, `uploader.yaml` 포함한 목록 반영(spec-v2 7절), brief의 "설명란·고정 댓글에 본편 링크"를 "관련 동영상 수동 연결 + 설명란에 본편 제목 텍스트"로 갱신.

완료 기준 추가: PC에서 `ffmpeg -version`과 `git pull`이 되고, 비밀 파일이 `git status`에 나타나지 않음.

## 1단계 MVP (변경)
- 순서 변경: 1-5 메타데이터를 렌더 앞으로(클라우드). 렌더는 **PC**에서 실행하고 `render-info.yaml`(해시)을 커밋. 승인은 렌더 후.
- 1-7 승인: `approval.yaml`에 `short_id`, `file_sha256`, `title` 기록. 완료 기준에 "렌더 후 파일을 바꾸면 업로더가 거부함(테스트)" 추가.
- 1-8 업로더: 업로드 성공 직후 로그 커밋·푸시 절차 포함. 업로드 전 채널 업로드 목록 이중 확인 구현 여부는 실측(9번) 후 결정.
- 1-9 실측: spec-v2 12절 1, 2, 3, 5, 7, 8, 9번.
- 완료 기준 추가: **실측 결과를 `youtube-upload` 스킬에 반영(총괄)**, 토큰 만료 시 재로그인 절차가 README에 있음, 후보 파일이 최소 버전 형식으로 작성·검증됨.

## 2~3단계
- v1과 동일. 단 2-1 scan은 `${SHORTS_SRC_ROOT}` 상대경로·전역 유일 ID 규칙을 검증하고, 2-6 배치 승인은 `approvals:` 목록에 쇼츠 ID·해시를 모두 적는 방식으로 한다.
- 실행 장소를 클라우드로 옮기고 싶다는 요구가 생기면(자동 업로드 서버 등) 토큰 보관·원본 접근 문제를 먼저 재설계한다(3단계 신규 후보, 비용 발생 가능).

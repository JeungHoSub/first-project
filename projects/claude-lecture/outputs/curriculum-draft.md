## 1편 위치 가정과 조정 방안
- 가정 A (가장 유력): 기존 1편은 입문 성격의 "Claude가 뭔가요" 류. 그러면 이 초안의 1회 자리에 두고, 나머지는 번호를 유지한다. 이 초안의 1회는 1편이 다룬 개념을 빼고 2회로 흡수한다.
- 가정 B: 1편이 프롬프트 요령을 다뤘다면, 1편을 2회 자리에 두고 이 초안의 1회는 "들어가기" 짧은 앞 회차(10분)로 따로 만든다. 번호는 1편 기준으로 다시 매긴다.
- 가정 C: 1편이 Claude Code나 에이전트까지 이미 다뤘다면, 앞쪽 회차를 줄여 합치고 1편의 말투를 기준으로 6~12회를 우선 제작한다.
- 어느 경우든 말투(존댓말 여부, 호칭, 오프닝 방식), 평균 길이, 비유 방식은 1편에 맞춘다. 이 초안의 제목과 순서는 그 뒤에 고친다.

## 회차 목록 (12회)

### 1회. Claude와 첫 만남: 똑똑한 동료에게 말 거는 법
- 한 줄 목표: Claude가 무엇이고, 어디서 쓰며, 어떤 한계가 있는지 감을 잡는다.
- 핵심 개념
  1. Claude는 대화로 일을 시키는 AI 어시스턴트다. 웹, 앱, Claude Code 등 여러 곳에서 같은 Claude를 쓴다.
  2. 한 대화에는 기억할 수 있는 양의 한계(컨텍스트 창)가 있다.
  3. 틀릴 수 있으니 중요한 건 확인한다.
- 비유: 지하철에서 처음 만난 박식한 옆자리 사람. 아는 척 잘하지만 내 사정은 모르니 내가 설명해야 한다.
- 실천 과제: 오늘 퇴근 후 Claude에게 오늘 점심 메뉴 고민을 한 번 상담해 본다. 답이 마음에 안 들면 이유를 말해 다시 시킨다.
- 예상 분량: 12분
- 기능 확인: 확인함(Claude Code 개요 페이지: 터미널, IDE, 데스크톱 앱, 웹에서 쓸 수 있고 같은 엔진을 쓴다는 설명). 컨텍스트 창 개념은 메모리 문서에서 "세션은 새 컨텍스트 창으로 시작한다"까지 확인함. ⚠️ 미확인: 현재 모델 라인업과 이름, 무료·유료 한도. 대본 쓸 때 재확인. ⚠️ 개념 1의 "웹, 앱, Claude Code에서 같은 Claude를 쓴다"는 문서로 확인된 범위가 Claude Code 실행 환경들 사이의 공통 엔진까지다. 웹·앱 Claude와 Claude Code가 같다는 부분은 미확인.

### 2회. 프롬프트 기본: 택시 기사님께 길 설명하듯
- 한 줄 목표: 목표, 맥락, 원하는 결과 모양을 담아 한 번에 알아듣게 요청한다.
- 핵심 개념
  1. 분명하고 직접적으로 말하기. 목표와 이유를 같이 준다.
  2. 맥락 주기. 누가 읽는지, 어디에 쓰는지.
  3. 결과 모양 정하기. 길이, 말투, 형식.
- 비유: 택시에서 "그냥 가주세요" 대신 "서울역, 빠른 길로, 9시 전 도착". 목적지, 사정, 원하는 방식.
- 실천 과제: 평소 쓰던 요청 하나를 골라 목표, 맥락, 형식 세 가지를 넣어 다시 써 보고 결과 차이를 비교한다.
- 예상 분량: 12분
- 기능 확인: 확인함(Claude 개발자 문서 "Prompt engineering overview": 명확성부터 예시, XML 구조화, 역할 부여, 사고 유도, 프롬프트 연결까지 기법이 "Prompting best practices" 문서에 정리돼 있음). ⚠️ 미확인: 세부 권장 문구는 대본 작성 때 best practices 페이지를 직접 읽고 확인.

### 3회. 프롬프트 심화: 예시 보여주기, 역할 주기, 단계 쪼개기
- 한 줄 목표: 결과가 들쭉날쭉할 때 쓰는 세 가지 손잡이를 익힌다.
- 핵심 개념
  1. 예시를 보여주면 말보다 빠르다.
  2. 역할을 주면 관점과 말투가 잡힌다.
  3. 큰 일은 단계로 쪼갠다. 한 단계 결과를 다음 단계 재료로 쓴다.
- 비유: 신입에게 업무 시킬 때 "지난번 이 보고서처럼"이라며 샘플을 건네는 것. 요리 레시피처럼 순서 나누기.
- 실천 과제: 내가 마음에 든 글 하나를 예시로 붙여서, 같은 느낌으로 새 글을 써 달라고 해 본다.
- 예상 분량: 14분
- 기능 확인: 확인함(Prompt engineering overview에서 예시, 역할, 단계 연결 기법 언급). ⚠️ 미확인: 각 기법의 최신 권장 방식. XML 태그는 청취용이라 대본에선 "구역을 나눠 이름 붙이기"로 풀 예정.

### 4회. 나를 기억시키기: 개인 지침과 프로젝트
- 한 줄 목표: 매번 같은 설명을 반복하지 않도록 지침과 프로젝트를 만든다.
- 핵심 개념
  1. 계정 전체에 적용되는 개인 지침(Instructions for Claude).
  2. 프로젝트: 자료와 지침이 담긴 전용 작업 공간.
  3. 한 번 써 두고 여러 대화에서 재활용하기.
- 비유: 단골 카페에 "늘 먹던 거요"가 통하는 것. 사장님이 내 취향 메모를 가지고 있는 상태.
- 실천 과제: 프로젝트 하나를 만들고 "이 프로젝트에서는 이렇게 답해 줘" 지침을 세 줄 적는다.
- 예상 분량: 13분
- 기능 확인: 확인함(support 문서 "What are projects": 지식 베이스와 프로젝트별 지침, 유료 플랜에서 RAG로 용량 확장, 공유는 Team·Enterprise). 확인함(support 문서 "Understanding Claude's personalization features": 계정 전체 지침은 설정의 "Your Claude" 아래). ⚠️ 미확인: 메모리 기능의 현재 제공 범위, 새 베타 프로젝트(클라우드 병렬 스레드)의 적용 범위. 요금제·한도는 자주 바뀌므로 대본 작성 시점에 재확인 필요.

### 5회. 취향 데이터 쌓기: 피드백이 자산이 되는 법
- 한 줄 목표: 내 문체·취향을 파일로 모아 어디서든 재활용하는 구조를 만든다.
- 핵심 개념
  1. 취향은 말로 흘리지 말고 한 파일에 쌓는다(이 저장소의 style 폴더, 학습된 선호).
  2. 피드백 한 줄이 다음 작업부터 반영되게 한다.
  3. 하나 만들어 여러 곳에 쓴다. 같은 스타일 파일을 강의, 쇼츠, 글에 돌려 쓰기.
- 비유: 이삿짐센터에 매번 설명하는 대신 "우리 집 취향 노트" 한 권을 만들어 두는 것. 가계부처럼 한 줄씩 쌓인다.
- 실천 과제: 이번 주 Claude 답변 중 마음에 든 것과 안 든 것을 각각 한 줄 이유와 함께 메모 파일에 적는다.
- 예상 분량: 12분
- 기능 확인: 이 회차는 개념 위주. 이 저장소 구조(style-guide.md의 "학습된 선호" 항목)는 직접 확인함. 공식 기능 설명은 최소.

### 6회. Claude Code 첫걸음: 대화에서 작업 현장으로
- 한 줄 목표: Claude Code가 대화형 챗과 어떻게 다른지, 어떤 작업에 쓰는지 안다.
- 핵심 개념
  1. Claude Code는 내 컴퓨터의 폴더를 읽고 파일을 고치고 명령을 실행하는 도구다.
  2. 쓰는 곳은 터미널, 에디터 확장, 데스크톱 앱, 웹으로 다양하지만 같은 엔진이다.
  3. 폴더가 곧 작업 공간. 어느 폴더에서 시작하느냐가 중요하다.
- 비유: 상담만 해 주는 컨설턴트와 직접 사무실에 들어와 서류를 정리해 주는 비서의 차이.
- 실천 과제: 연습용 빈 폴더 하나를 만들고 Claude Code에게 "이 폴더에 메모 파일 하나 만들어 줘"라고 시켜 본다. 설치는 공식 안내를 따른다.
- 예상 분량: 14분
- 기능 확인: 확인함(code.claude.com Overview: 정의, 실행 환경, 설치는 터미널·데스크톱 앱 등, 대부분 구독 또는 콘솔 계정 필요, 데스크톱은 유료 구독 필요). ⚠️ 재확인 필요: 요금제·구독 조건은 자주 바뀜. 설치 명령은 청취용이라 대본에서 읽지 않고 "공식 설치 안내를 따른다"로 처리.

### 7회. Claude의 기억 장치: CLAUDE.md와 자동 메모리
- 한 줄 목표: 세션이 바뀌어도 이어지는 지침을 폴더에 심는다.
- 핵심 개념
  1. 세션은 매번 백지에서 시작한다. 그래서 읽어 줄 지침 파일이 필요하다.
  2. CLAUDE.md는 내가 쓰는 지침, 자동 메모리는 Claude가 스스로 적는 메모.
  3. 짧고 구체적일수록 잘 지켜진다. 지침은 강제가 아니라 참고 맥락이다. (훅 같은 별도 강제 장치는 "있다" 정도만 한 문장으로 언급, 설명은 하지 않음. 개념 수 3개 유지)
- 비유: 출근하면 책상 위에 놓인 인수인계 포스트잇. 매일 기억 리셋되는 직원에게 붙여 두는 메모.
- 실천 과제: 연습 폴더에 CLAUDE.md를 만들고 규칙 세 줄을 적은 뒤, 새 세션에서 지켜지는지 확인한다.
- 예상 분량: 14분
- 기능 확인: 확인함(code.claude.com "How Claude remembers your project": 세션은 새 컨텍스트로 시작, CLAUDE.md는 사용자가 쓰고 자동 메모리는 Claude가 씀, 둘 다 매 세션 로드, 지침은 강제가 아닌 맥락, init 명령으로 초안 생성, 메모리 명령으로 자동 메모리 토글). ⚠️ 미확인: CLAUDE.md 적정 길이의 공식 권장치(대본 때 확인).

### 8회. 스킬: 반복 업무를 절차서로 만들기
- 한 줄 목표: 자주 하는 일을 스킬로 한 번 만들어 계속 재활용한다.
- 핵심 개념
  1. 스킬은 SKILL.md가 든 폴더. 설명문을 보고 Claude가 알아서 꺼내 쓰거나 내가 슬래시로 부른다.
  2. 어디에 두느냐(개인, 프로젝트)에 따라 쓰이는 범위가 달라진다. 프로젝트에 두고 커밋하면 팀과 공유.
  3. 설명문(description)을 잘 쓰는 게 핵심이다. 언제 쓰는지가 들어가야 한다.
- 비유: 라면 끓이는 법이 적힌 봉지 뒷면. 한 번 적어 두면 누구든, 언제든 같은 맛.
- 사례: 이 저장소의 audio-lecture-script, handoff, request-review 스킬.
- 실천 과제: 내가 반복해서 시키는 일 하나를 골라 스킬 폴더를 만들고 설명문 두 줄과 절차 세 줄을 쓴다.
- 예상 분량: 15분
- 기능 확인: 확인함(code.claude.com Skills: 위치 표, SKILL.md 구조, name·description 필드, 자동 호출과 수동 호출, disable-model-invocation, 설명문 길이 제한). 이전 방식 commands 폴더도 여전히 동작함.

### 9회. 서브에이전트: 역할별 전문가에게 나눠 맡기기
- 한 줄 목표: 역할별 에이전트가 무엇이고 왜 나누는지 이해한다.
- 핵심 개념
  1. 서브에이전트는 독립된 대화창(컨텍스트)을 가진 전문가. 끝나면 요약만 돌려준다.
  2. 이름, 설명, 쓸 수 있는 도구를 정해 권한을 좁힌다(예: 읽기·검색 도구만 주는 조사 담당. 이 저장소의 reviewer는 파일 수정 도구도 가지고 있어 완전한 읽기 전용은 아니다).
  3. 프로젝트별이 아니라 역할별로 만들어 여러 프로젝트가 같이 쓴다.
- 비유: 회사의 기획팀, 디자인팀, 검수팀. 일은 나누되 각자 자기 서랍(컨텍스트)만 쓴다.
- 사례: 이 저장소의 lecture-writer, reviewer, planner, developer 등 역할별 에이전트.
- 실천 과제: 도구를 읽기·검색으로만 좁힌 "검수자" 에이전트 파일을 하나 만들고, 내 글 하나를 검수시킨다.
- 예상 분량: 15분
- 기능 확인: 확인함(code.claude.com Sub-agents: 정의 위치 .claude/agents, 필수 필드 name·description, tools로 도구 제한, 별도 컨텍스트 창, 요약만 반환, 사용량에는 포함됨, 에이전트 관리 명령). ⚠️ 미확인: 문서 마지막 일부(약 17,000자)는 읽지 못함. 모델 지정 값의 최신 목록은 대본 때 재확인.

### 10회. 일 넘기는 법: 파일 인계, 로그, 검토 대기열
- 한 줄 목표: 에이전트끼리, 그리고 나와 에이전트 사이에 일이 끊기지 않게 하는 기록 습관을 익힌다.
- 핵심 개념
  1. 결과물은 말이 아니라 파일로 남긴다(outputs 폴더).
  2. log.md에 한 일, 다음 담당, 넘길 메모를 적는다.
  3. 내가 볼 곳은 한 곳(review/QUEUE.md). 검토 후 피드백은 다음 작업에 반영된다.
- 비유: 교대 근무 인수인계 노트와 택배 송장. 받는 사람이 설명 없이도 이어서 일하게.
- 사례: 이 저장소의 handoff, request-review 스킬과 reviewer 단계.
- 실천 과제: 오늘 한 일을 "한 일, 결과물, 다음 할 일" 세 줄로 로그 파일에 남겨 본다.
- 예상 분량: 13분
- 기능 확인: 저장소 자체 규칙 기반(CLAUDE.md, SESSIONS.md 직접 확인). 공식 기능 설명은 적음.

### 11회. 여러 세션 운영: 프로젝트 하나에 세션 하나
- 한 줄 목표: 여러 프로젝트를 섞이지 않게 굴리는 운영 규칙을 익힌다.
- 핵심 개념
  1. 프로젝트 1개 = 세션 1개. 대화 맥락이 섞이지 않고 비용도 덜 든다.
  2. 모두 같은 저장소를 쓰니 에이전트, 스킬, 스타일은 공유되고 결과물은 각자 폴더에 쌓인다.
  3. 충돌 방지: 자기 폴더만 고치고, 공용 파일은 최신을 받아 합친 뒤 커밋한다. 세션 끝나기 전 커밋과 다음 할 일 기록.
- 비유: 한 건물 안의 여러 사무실. 공용 복도(공용 폴더)를 쓸 땐 서로 부딪히지 않게 규칙이 필요.
- 사례: 이 저장소의 SESSIONS.md, 총괄(메인 세션) 규칙, 프로젝트별 담당 흐름.
- 실천 과제: 지금 하는 일 두 가지를 섞지 말고 각각 다른 대화(세션)로 나눠서 진행해 본다.
- 예상 분량: 15분
- 기능 확인: 저장소 규칙 직접 확인. 에이전트 팀·병렬 세션 관련 공식 기능은 Overview에서 "백그라운드 에이전트", "병렬 에이전트" 언급만 확인함. ⚠️ 미확인: 병렬 세션을 한 화면에서 보는 기능의 정확한 이름과 제공 조건(대본 때 해당 문서 확인).

### 12회. 어디서든 이어가기: Remote Control과 전체 지도
- 한 줄 목표: 자리를 떠나서도 세션을 이어가는 방법과, 11회분을 하나의 지도로 정리한다.
- 핵심 개념
  1. Remote Control은 내 컴퓨터에서 돌아가는 세션을 폰이나 다른 브라우저에서 이어 쓰는 기능이다. 실행은 계속 내 컴퓨터에서 한다.
  2. 시작은 새로 켜기, 실행 중인 세션에서 슬래시 명령으로 켜기 등이 있고, 연결 상태 표시와 QR로 다른 기기에 접속한다.
  3. 지금까지의 전체 지도: 대화, 프롬프트, 지침과 프로젝트, 스타일, Claude Code, 기억 파일, 스킬, 에이전트, 인계, 세션 운영.
- 비유: 집 컴퓨터를 켜 둔 채 지하철에서 폰으로 이어 보는 원격 책상. 일은 집에서 돌고 나는 리모컨만 든다.
- 실천 과제: 12회 전체 중 내 일상에 가장 쓸모 있는 한 가지를 골라 이번 주에 실제로 적용해 본다.
- 예상 분량: 15분
- 기능 확인: 확인함(code.claude.com Remote Control: 로컬에서 계속 실행, 폰·브라우저 연결, Pro·Max·Ultra·Team·Enterprise 플랜, API 키는 미지원, Team·Enterprise는 관리자가 켜야 함, 서버 모드·대화형 플래그·세션 중 슬래시 명령(rc 약어) 세 방식, 상태 패널에서 URL과 QR 표시). 웹판 Claude Code와는 "내 컴퓨터에서 실행하느냐 클라우드냐"로 구분. 요금제 조건은 자주 바뀌므로 대본 작성 시점에 재확인 필요. 청취용이라 명령어는 말로만 소개. ⚠️ 미확인(검수 추가): 지원 플랜 이름 목록(특히 "Ultra"의 존재·표기)과 일부 항목은 검색으로만 확인한 것이라 대본 전에 원문 페이지에서 재확인.

# 커리큘럼 임시 초안 검수 결과

대상: `projects/claude-lecture/outputs/curriculum-draft.md` / 검수일 2026-11-12 / 검수: reviewer

## 판정: 수정 후 통과 (임시 초안으로서)
기존 1편이 들어오기 전의 임시 초안이라는 전제에서 통과. 확실한 사실 오류와 미확인 표시 누락 4건은 직접 고쳤고, 구성 관련 사항은 제안으로만 남긴다. 1편 확인 후 재검수 필요.

## 통과 항목
- 맨 위 "기존 1편 확인 후 말투·구성 조정 예정" 표시 있음(3~5행). 가정 A/B/C 조정안도 있음.
- 회차당 개념 3개 이하: 12회 모두 3개. 단 7회 3번이 사실상 2개 내용이라 직접 고침(아래).
- 흐름: 기본(1) → 프롬프트(2~3) → 프로젝트·스타일(4~5) → Claude Code(6~7) → 스킬·에이전트(8~9) → 인계·여러 세션(10~12). 요청한 순서와 일치.
- 일상 비유(택시, 단골 카페, 인수인계 포스트잇 등)와 학습된 선호 두 가지(풀어서 일상과 엮기, 하나 만들어 재활용)가 반영됨. 재활용은 4, 5, 8회에 명시.
- 저장소 사례 대조: `.claude/agents`의 lecture-writer, reviewer, planner, developer와 `.claude/skills`의 audio-lecture-script, handoff, request-review가 실제로 존재. "프로젝트별이 아니라 역할별 에이전트"(CLAUDE.md), "프로젝트 1개 = 세션 1개", 충돌 방지 규칙(SESSIONS.md), style-guide의 "학습된 선호"도 사실과 일치.
- 확인함/미확인 구분과 미확인 목록, 사용자에게 확인할 질문(추천안 표시)이 있어 판단 요청 방식도 CLAUDE.md 원칙에 맞음.

## 직접 수정한 항목 (curriculum-draft.md)
1. **9회 핵심 개념 2·실천 과제, 사실 오류**: "예: 읽기 전용 검수자"라고 했으나 이 저장소 `reviewer.md`의 도구는 `Read, Glob, Grep, Edit, Write`로 수정 권한이 있다. 사례로 reviewer를 쓰면서 읽기 전용이라 말하면 틀린다. 예시를 "읽기·검색 도구만 주는 조사 담당"으로 바꾸고 reviewer는 완전한 읽기 전용이 아니라는 주석을 추가했다. 실천 과제도 "도구를 읽기·검색으로만 좁힌 검수자"로 정정.
2. **7회 핵심 개념 3, 개념 수**: "짧고 구체적일수록" + "훅이라는 별도 장치"가 한 줄에 두 개념이라 4개처럼 된다. 훅은 "있다"는 한 문장 언급만 하고 설명하지 않는다고 명시해 3개 유지.
3. **1회 기능 확인, 과장 소지**: "웹, 앱, Claude Code에서 같은 Claude를 쓴다"는 근거인 Claude Code 개요 문서가 확인해 준 것은 Claude Code의 여러 실행 환경이 같은 엔진이라는 점까지다. 웹·앱 Claude와 같다는 부분은 ⚠️ 미확인으로 표시.
4. **12회 기능 확인, 미확인 표시 누락**: "Pro·Max·Ultra·Team·Enterprise" 플랜 이름 중 Ultra는 존재와 표기가 의심스럽다. 기능 확인 표에는 "일부는 검색으로만 확인"이라 돼 있는데 회차 본문에는 그 단서가 없었다. ⚠️ 미확인 문구 추가.

## 수정 필요 (제안만, 직접 고치지 않음)
1. **가정 A 설명이 모순(18행)**: "1편을 1회 자리에 두고" 이후 "초안 1회 개념은 빼고 2회로 흡수"라고 했다. 2회는 이미 개념 3개라 흡수하면 3개를 넘는다. 제안: "1편과 겹치는 개념은 삭제하고, 남는 개념만 2회에 넣되 2회가 3개를 넘으면 3회로 이월"처럼 규칙을 바꾼다.
2. **5회 위치**: 5회가 저장소의 style 폴더와 파일 기반 취향 관리를 쓰는데 Claude Code 소개(6회)보다 앞이다. 청취자는 "폴더에 파일로 쌓는다"는 전제를 아직 모른다. 제안: (a) 5회를 웹 프로젝트·메모 파일 수준으로 낮추고 저장소 사례는 7회 이후로 미루거나, (b) 5회와 6회 순서를 바꾼다. 어느 쪽인지는 1편의 구성을 보고 결정.
3. **6회 핵심 개념 1과 2의 불일치**: "내 컴퓨터의 폴더를 읽고 고친다"고 하면서 쓰는 곳에 웹이 들어가 있다. 12회에서 웹판은 클라우드 실행이라고 구분하므로, 6회에서도 "내 컴퓨터 또는 클라우드의 작업 폴더"로 맞추거나 웹은 12회로 미룬다.
4. **12회 구성**: Remote Control(원격 이어가기)과 전체 지도 복습이 한 회에 섞여 있다. 개념 2번이 명령 방식 설명 위주라 "명령어는 말로만"과도 안 맞는다. 제안: 2번은 "켜는 방식이 여러 가지, 세부는 공식 안내"로 줄이고, 전체 지도는 클로징 복습으로 돌리거나 별도 마무리 회로 분리. 또 후반부(8~12회)가 저장소 사례를 쓴다고 했지만 12회는 사례가 없다.
5. **분량 기준 불일치**: 초안은 3,000~6,000자(스킬 기준), brief는 약 3,000~5,000자. 12~15분(약 3,600~4,500자)은 둘 다 만족하지만, 공통 원칙에 brief 기준(3,000~5,000자)도 함께 적어 두는 게 안전하다.
6. **빈틈(선택)**: (a) Claude Code의 권한 허락(파일 수정·명령 실행 승인)과 안전 습관이 6회에 없다. 처음 쓰는 사람에게 필수. (b) 민감정보를 입력하지 말라는 주의가 1회나 4회에 없다. (c) 외부 도구 연결(MCP)은 어디에도 없다. 범위 밖이면 "다루지 않음"으로 명시. 1~3개 정도를 6회 또는 11~12회에 한 문장씩 넣는 것을 제안.
7. **중복 점검**: 4회 3번(재활용), 5회 3번(재활용), 8회(스킬 재활용)가 비슷하다. 의도된 반복이면 "이전 회의 그 재활용이 이번엔 이것"처럼 연결해서 복습 효과를 살리고, 아니면 4회 3번을 줄인다. 5회 2번(피드백 반영)과 10회 3번(검토 후 피드백 반영)도 같은 맥락이니 10회에서는 5회를 명시적으로 이어받게 한다.
8. **듣기 환경**: 대본 단계에서 지킬 점. 8·9회 실천 과제(스킬 폴더, 에이전트 파일 작성)는 귀로 들은 뒤 책상에서 하는 작업이라 "퇴근 후"로 시점을 적고, 파일 형식 설명은 말로 풀 것. 초안 내 URL, 표, 슬래시 명령은 작업 메모에만 있고 대본에는 넣지 않는다는 원칙이 이미 6·12회에 있으니 8회 슬래시 호출도 같은 처리.
9. **확인 메모의 한계**: 8·9회 공식 문서 말미 약 19,000자/17,000자는 미열람. 8·9회의 "확인함"은 그 범위 한정임을 대본 단계에서 다시 상기.

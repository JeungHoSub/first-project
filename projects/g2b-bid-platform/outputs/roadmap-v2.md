## 단계별 상세

### D0. 준비·확인 (S1)

| 항목 | 내용 |
|---|---|
| 할 일 | (1) data.go.kr 서비스키 발급 (아래 단계별 안내) (2) 텔레그램 봇 만들기(BotFather) (3) spec-v2 16장 미확인 8개 항목 확인 (4) g2b-bid-data 스킬에 확정된 오퍼레이션 이름·7일 조회기간 반영 (5) 조건 초안: 전 업종·전국이라 제외어 몇 개만 먼저 정하기 |
| 담당 | 사용자(키 발급, 봇 만들기) / 총괄 세션(curl로 참고문서·활용신청 화면 확인) / researcher(결과 정리·스킬 문서안) / skill-scout(텔레그램 연동 스킬 유무 확인) |
| 작업량 | 사용자 1~2시간 + 확인 반나절 |
| 완료 기준 | 서비스키가 `.env`에 있고 채팅·git에 없음 / 미확인 8개가 표로 채워짐(특히 numOfRows 최대, 트래픽 단위, 공공누리 유형) / g2b-bid-data 스킬 수정안 반영 |

서비스키 발급 단계별 안내 (화면 문구는 사이트 개편으로 조금 다를 수 있음):

1. 브라우저에서 data.go.kr에 접속해 로그인한다. 회원이 아니면 가입한다. 로그인된 이름이 오른쪽 위에 보이면 성공이다.
2. 상단 검색창에 "조달청 나라장터 입찰공고정보서비스"를 입력하고 검색한다. 결과에서 같은 이름의 오픈API 항목이 보인다.
3. 그 항목을 눌러 상세 페이지를 연다. 개발계정 트래픽, 이용허락범위, 참고문서(첨부파일) 목록이 보인다. (이 화면의 트래픽·이용허락범위 값이 D0 확인 항목 2·3번이다.)
4. 오른쪽의 [활용신청] 버튼을 누른다. 활용 목적을 적는 입력창이 나타난다.
5. 활용 목적에 "나라장터 입찰 공고 알림 서비스 개발" 정도로 적고 약관에 동의한 뒤 신청을 누른다. 자동승인이라 신청 직후 승인 상태로 바뀐다 [직접 확인: 심의 자동승인].
6. 마이페이지의 개발계정(활용 현황) 목록에서 방금 신청한 서비스를 연다. 일반 인증키(Encoding / Decoding 두 종류)가 보인다.
7. 인증키를 복사해 프로젝트의 `.env` 파일에만 붙여 넣는다. 채팅·메모·문서에는 붙이지 않는다. 어느 쪽 키(Encoding/Decoding)를 쓸지는 developer가 D1 첫날 시험 호출로 정한다.
8. 같은 방법으로 낙찰정보서비스, 사전규격정보서비스, 공공데이터개방표준서비스도 신청한다. 모두 무료·자동승인이므로 비용이 없고, 입찰공고정보서비스만 필수다. 인증키가 서비스마다 따로 나오면 `.env`에 이름을 구분해 넣는다.
9. 활성화까지 시간이 걸릴 수 있다(몇 분~1시간 정도 [추정]). 키가 바로 안 되면 잠시 후 다시 시험한다.

텔레그램 봇 만들기 단계별 안내:

1. 텔레그램 앱에서 "BotFather"를 검색해 공식 계정(파란 체크 표시)을 연다.
2. 대화창에 `/newbot`을 보낸다. 봇 이름을 물어보는 답이 온다.
3. 봇 이름과 봇 아이디(끝이 bot으로 끝나는 이름)를 차례로 보낸다. 완료 메시지에 봇 토큰이 나온다.
4. 토큰을 `.env`에만 붙여 넣는다. 채팅에는 붙이지 않는다.
5. 만든 봇을 검색해 열고 `/start`를 보낸다. 이것이 chat id를 연결하는 첫 단계다.

기간: 4개월 = 무료 3개월 + 유료 전환 확인 1개월 (M-7 해소).

| 기간 | 할 일 | 담당 |

| 1~3개월차 | 지인 3~5곳 온보딩, 1~2주마다 피드백, 불편 반영. 요금은 받지 않음 | 사용자(응대) + developer + planner |

| 4개월차 | 실제 결제(계좌이체 가능) 확인, 월 원가 대비 수익 계산 | 사용자 + planner |

## 위험과 대응

| 위험 | 영향 | 대응 |
|---|---|---|
| 한 페이지 행 수(R)가 작거나 단위가 행 수 | 개발계정 1,000 초과, 수집 중단 | D0에서 R·단위 확인, 경고 임계치 700/900, 운영계정 증량(D3 직후), 개방표준(일 10,000) 보조 수집, 수집 주기 완화 |
| 조회기간 7일 제한 | 백필·따라잡기 호출 증가 | 7일 조각 설계, 백필은 MVP에서 7일만, 하루 400회 상한 |
| 정정공고를 놓침 | 오래된 정보로 알림 | D0에서 변경일시 기준 조회 여부 확인, 겹침 1시간 + 완전성 검사 |
| 전 업종·전국이라 묶음이 너무 김 | 알림을 안 읽게 됨 | 건수 상한 50, 맨 윗줄 요약, 마감 임박 먼저, D5에서 좁히는 도구 |
| 담당자 연락처가 DB에 저장됨 | 개인정보 위험 | 허용 필드만 저장, 정규식 점검(D1·D4) |
| 서비스키·봇 토큰이 로그·git에 노출 | 키 도용 | 마스킹, `.env.example`, 유출 시 재발급 절차 |
| 공공누리 유형·상업 이용 조건 미확인 | 판매 불가 가능성 | D0·D6에서 확인, 안 되면 S2 재검토. 이용허락범위는 "제한 없음"이라 위험은 낮다고 보임 |
| 가격 차별이 약함(이비드 12개월 환산과 8.8% 차이) | 판매 어려움 | 묶음 알림·낙찰률 같은 좁은 기능, 지인 네트워크. 경쟁사 요금 중 일부는 미확인이라 "가장 싸다" 홍보 금지 |
| PC가 꺼짐(실행 환경 PC 선택 시) | 발송 지연 | 7일 조각 따라잡기로 데이터는 보존, 안정화되면 VPS 이전 |
| 지인 지원 부담 | 내 시간 소모 | 파일럿 3~5곳 제한, 온보딩 절차 문서화 |

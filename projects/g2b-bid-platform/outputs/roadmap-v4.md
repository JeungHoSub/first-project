# 입찰 플랫폼 로드맵 (roadmap-v4)

작성: planner / 2026-11-16 / 짝 문서: spec-v4.md
기존 roadmap.md(v1), roadmap-v2.md, roadmap-v3.md는 그대로 둔다. 작업량은 "집중해서 하는 하루" 기준의 대략치이며 [추정]이다.
사용자 질문은 spec-v4.md 맨 끝 한 곳에만 있다(이번에는 없음).

## 사용자가 지금 할 일

D0을 시작하려면 아래 네 가지를 사용자가 직접 해야 한다. 순서대로 하면 된다. 예상 시간은 합쳐서 1~2시간 [추정].

### 0. 먼저 읽기

- **서비스키와 봇 토큰은 채팅에 붙이지 않는다.** 이 둘은 남이 보면 내 계정으로 호출하거나 내 봇을 조종할 수 있는 비밀번호다. 아래 단계에서 PC의 메모 파일에만 저장한다. 채팅에는 "발급했다"는 말만 적는다.
- 화면 캡처를 올려야 할 때도 키·토큰이 보이는 화면은 올리지 않는다.
- 단계마다 행동은 하나다. 한 단계가 끝나면 "그 결과 보이는 것"과 비교해서 맞으면 다음으로 간다.
- **[화면 미확인]** 표시는 "내가 실제 화면을 열어 보지 않고 쓴 버튼·메뉴 이름"이라는 뜻이다. 화면이 다르면 가장 비슷한 것을 누르고, 어디가 달랐는지 채팅에 알려 준다(키 값은 빼고). D0에서 총괄이 실제 화면에 맞춰 이 문서를 고치고 표시를 지운다(spec-v4 16장 11번).

공통 A. 명령 프롬프트(검은 글자창) 열기 (아래에서 "공통 A"로 부른다)

1. 키보드의 Windows 키를 누른다. 시작 메뉴가 열린다.
2. `cmd`를 입력한다. 검색 결과 맨 위에 [명령 프롬프트]가 보인다. [화면 미확인]
3. Enter를 누른다. 검은 창이 열리고 `C:\Users\...>` 같은 글자가 보인다.

### 1. 키 보관 폴더와 메모 파일 만들기 (프로젝트 밖, git에 올라가지 않는 곳)

코드가 PC에 오기 전까지(D1 시작 전) 키를 잠깐 보관할 곳이다. D1 첫날 developer 안내에 따라 `.env`로 옮기고 이 파일은 지운다.

1. 공통 A로 명령 프롬프트를 연다.
2. `mkdir C:\g2b-secrets`를 입력하고 Enter를 누른다. 아무 메시지 없이 다음 줄로 넘어가면 성공이다.
3. `notepad C:\g2b-secrets\keys.env`를 입력하고 Enter를 누른다. "새 파일을 만들까요?" 같은 물음창이 뜬다. [화면 미확인]
4. [예]를 누른다. 제목이 `keys.env`인 빈 메모장이 열린다.
5. 이 메모장 창은 닫지 않고 둔다. 아래 2·3번에서 키를 여기에 붙여 넣는다.

### 2. 공공데이터포털(data.go.kr) 서비스키 발급

입찰공고정보서비스 한 가지만 지금 필요하다. 낙찰정보·사전규격정보·개방표준 서비스는 D0 확인 8·9번에서 필요하다고 판단되면 총괄이 요청하며, 그때는 2-B부터 2-D만 같은 방식으로 한다(로그인은 이미 되어 있다).

**2-A. 로그인**

1. 브라우저(Edge 또는 Chrome)를 연다. 빈 창이 열린다.
2. 주소창에 `data.go.kr`을 입력하고 Enter를 누른다. 공공데이터포털 첫 화면이 보인다.
3. 화면 오른쪽 위의 [로그인]을 누른다. [화면 미확인] 로그인 화면이 열린다.
4. (회원이 아닌 경우만) [회원가입]을 누르고 가입을 끝낸다. [화면 미확인] 끝나면 로그인 화면으로 돌아온다.
5. 아이디 칸에 아이디를 입력한다.
6. 비밀번호 칸에 비밀번호를 입력한다.
7. [로그인] 버튼을 누른다. [화면 미확인] 화면 오른쪽 위에 내 이름이 보이면 성공이다.

**2-B. 서비스 찾기**

1. 화면 위쪽의 검색창을 누른다. 커서가 깜빡인다.
2. `조달청 나라장터 입찰공고정보서비스`를 입력한다.
3. Enter를 누른다. 검색 결과 목록이 나온다.
4. 결과에서 이름이 같고 데이터 종류가 오픈API로 표시된 항목을 누른다. [화면 미확인] 상세 페이지가 열린다.
5. 상세 페이지에 "입찰공고정보서비스"라는 제목과 개발계정 트래픽, 이용허락범위 칸이 보이는지 확인한다. [화면 미확인] 보이면 제대로 찾은 것이다.

**2-C. 활용신청**

1. 상세 페이지의 [활용신청] 버튼을 누른다. [화면 미확인] 신청 입력 화면이 열린다.
2. 활용목적 칸에 `나라장터 입찰 공고 알림 서비스 개발(개인 사용)`을 입력한다. 사실과 다르게 쓰지 않는다. [화면 미확인]
3. 이용약관 동의 칸을 체크한다. [화면 미확인] 체크 표시가 생긴다.
4. [신청] 버튼을 누른다. [화면 미확인] 신청 완료 안내가 나온다.
5. 승인 상태를 본다. 활용신청 심의는 자동승인이라고 안내되어 있다 [직접 확인]. 바로 승인으로 바뀌지 않으면 잠시 뒤 새로 고침(F5)한다.

**2-D. 인증키 복사해서 보관 (13단계 모순 해소: Encoding과 Decoding을 따로 복사한다)**

사용할 키가 Encoding인지 Decoding인지는 developer가 D1 첫날 시험 호출로 정한다. 그래서 두 가지를 모두 보관한다.

1. 화면 오른쪽 위의 [마이페이지]를 누른다. [화면 미확인] 내 정보 화면이 열린다.
2. 왼쪽 메뉴에서 개발계정(또는 활용 현황)을 누른다. [화면 미확인] 신청한 서비스 목록이 보인다.
3. 목록에서 방금 신청한 서비스 이름을 누른다. 인증키가 보이는 상세 화면이 열린다.
4. 일반 인증키 중 Encoding이라고 적힌 키를 마우스로 끌어 선택한다. [화면 미확인] 키 글자가 파랗게 칠해진다.
5. 키보드에서 Ctrl+C를 누른다. 겉으로 보이는 변화는 없다.
6. 1번에서 열어 둔 메모장 창으로 Alt+Tab으로 돌아간다. 메모장이 앞에 나온다.
7. 메모장에 `DATA_GO_KR_KEY_ENCODING=`를 입력한다. (이름은 D1에서 developer가 바꿀 수 있다.)
8. 바로 뒤에 Ctrl+V를 눌러 붙여 넣는다. 한 줄에 `이름=키`가 이어서 보인다.
9. Enter를 눌러 새 줄로 간다.
10. Alt+Tab으로 브라우저로 돌아간다. 인증키 화면이 보인다.
11. 이번에는 Decoding이라고 적힌 키를 끌어 선택하고 Ctrl+C를 누른다. [화면 미확인]
12. Alt+Tab으로 메모장으로 돌아간다.
13. 새 줄에 `DATA_GO_KR_KEY_DECODING=`을 입력한다.
14. 바로 뒤에 Ctrl+V를 눌러 붙여 넣는다. 두 줄이 보인다.
15. Ctrl+S를 눌러 저장한다. 제목 표시줄에 `keys.env`가 보이고 별표(*)가 없다.
16. 메모장 창은 닫지 않고 둔다(아래 3번에서 봇 토큰도 넣는다).
17. 키가 아직 안 먹히면 기다린다. 활성화까지 몇 분~1시간 걸릴 수 있다 [추정]. 사용자가 할 일은 기다리는 것뿐이다.

**2-E. D0 확인용 참고문서 받기 (키가 들어 있지 않은 문서)**

1. 서비스 상세 페이지로 돌아간다. 2-B 5번 화면이 보인다. (브라우저 뒤로 가기)
2. 참고문서(첨부파일) 목록에서 파일 이름을 누른다. [화면 미확인] 파일이 내려받아진다.
3. 파일 탐색기에서 다운로드 폴더를 열고 받은 파일을 찾는다.
4. 그 파일을 채팅창으로 끌어다 놓아 올린다. 참고문서에는 키가 없다. 마이페이지 화면은 올리지 않는다.

### 3. 텔레그램 봇 만들기

토큰을 PC 메모장으로 복사해야 하므로 PC에서 텔레그램을 연다.

**3-A. PC에서 텔레그램 열기**

1. PC에 텔레그램 앱이 이미 설치되어 있으면 열고 3-B로 간다. 없으면 다음 단계로 간다.
2. 브라우저 주소창에 `web.telegram.org`를 입력하고 Enter를 누른다. QR 코드 로그인 화면이 보인다. [화면 미확인]
3. 폰의 텔레그램 앱에서 [설정]을 누른다. [화면 미확인]
4. [기기]를 누른다. [화면 미확인]
5. [데스크톱 기기 연결]을 누른다. 카메라가 켜진다. [화면 미확인]
6. 카메라로 PC 화면의 QR 코드를 비춘다. PC 화면에 내 대화 목록이 나타난다.

**3-B. BotFather로 봇 만들기**

1. 텔레그램 검색창을 누른다.
2. `BotFather`를 입력한다. 검색 결과가 나온다.
3. 이름 옆에 파란 체크 표시가 있는 BotFather를 누른다. 대화창이 열린다. (체크 표시가 없는 비슷한 이름은 가짜일 수 있어 누르지 않는다.)
4. 대화창 아래의 [시작](START) 버튼을 누른다. [화면 미확인] BotFather가 명령 목록을 보낸다.
5. `/newbot`을 입력하고 전송한다. 봇 이름을 물어보는 답이 온다.
6. 화면에 보일 봇 이름(예: 입찰알리미)을 입력하고 전송한다. 봇 아이디를 물어보는 답이 온다.
7. 끝이 `bot`으로 끝나는 영문 아이디(예: `my_bid_alert_bot`)를 입력하고 전송한다. 이미 쓰인 아이디면 다른 것을 쓰라는 답이 온다. 성공하면 완료 메시지가 오고 그 안에 봇 토큰이 보인다.
8. 토큰(숫자와 글자가 섞인 긴 문자열)을 마우스로 끌어 선택한다. [화면 미확인]
9. Ctrl+C를 누른다. 겉으로 보이는 변화는 없다.
10. 메모장 창으로 Alt+Tab으로 돌아간다.
11. 세 번째 줄에 `TELEGRAM_BOT_TOKEN=`을 입력하고 바로 뒤에 Ctrl+V로 붙여 넣는다. 세 줄이 보인다.
12. Ctrl+S를 눌러 저장한다. 제목 표시줄에 별표(*)가 없다.
13. 메모장 창을 닫는다. 키와 토큰이 `C:\g2b-secrets\keys.env`에 저장됐다.
14. 텔레그램으로 돌아와, BotFather 대화창에 남은 토큰 메시지가 있다는 것을 기억해 둔다. 이 PC를 다른 사람과 같이 쓰면 그 대화를 지운다. (혼자 쓰면 그대로 둬도 된다.)

**3-C. 내 봇과 대화창 열어 보기**

1. 텔레그램 검색창에 방금 만든 봇 아이디를 입력한다. 검색 결과에 내 봇이 보인다.
2. 내 봇을 누른다. 빈 대화창이 열린다.
3. [시작](START) 버튼을 누른다. [화면 미확인] `/start`가 전송된다.
4. 봇이 답하지 않는 것이 정상임을 확인한다. 답장은 D2에서 만든다. D2에서는 `/start 연결코드` 형식으로 다시 보내게 된다(spec-v4 10-1).

### 4. PC 준비 (Windows)

**4-A. Python 설치**

1. 브라우저 주소창에 `python.org/downloads`를 입력하고 Enter를 누른다. 파이썬 공식 다운로드 화면이 보인다.
2. 맨 위의 큰 [Download Python 3.x.x] 버튼을 누른다. 숫자는 그때 최신 안정 버전이며 3.12 이상이면 된다 [추정]. [화면 미확인] 설치 파일(.exe)이 내려받아진다.
3. 내려받은 설치 파일을 두 번 누른다. 설치 창이 열린다.
4. 설치 창 맨 아래의 [Add python.exe to PATH] 칸을 체크한다. 체크 표시가 생긴다. [화면 미확인] (이걸 빼먹으면 뒤의 명령이 안 먹는다.)
5. [Install Now]를 누른다. [화면 미확인] 진행 막대가 차오른다.
6. "Setup was successful"이 보이면 [Close]를 누른다. [화면 미확인]
7. 공통 A로 명령 프롬프트를 연다. (이미 열려 있던 창은 닫고 새로 연다.)
8. `python --version`을 입력하고 Enter를 누른다. `Python 3.x.x`가 보인다.
9. `python -m pip --version`을 입력하고 Enter를 누른다. `pip ...` 버전이 보인다.
10. 8번에서 "Python을 찾을 수 없습니다" 같은 말이나 마이크로소프트 스토어 창이 나오면, 설치 프로그램을 다시 열고 4번 체크를 확인한 뒤 다시 설치한다. 그래도 안 되면 그 문구를 채팅에 알려 준다.

**4-B. PC가 잠들지 않게 하기** (30분마다 자동 실행하려면 PC가 깨어 있어야 한다)

1. 키보드의 Windows 키를 누른다. 시작 메뉴가 열린다.
2. [설정](톱니바퀴 아이콘)을 누른다. [화면 미확인] 설정 창이 열린다.
3. [시스템]을 누른다. [화면 미확인]
4. [전원 및 배터리](Windows 10은 [전원 및 절전])를 누른다. [화면 미확인]
5. [화면 및 절전] 항목을 눌러 펼친다. [화면 미확인] 시간 선택 칸들이 보인다.
6. "전원에 연결 시 PC를 절전 모드로 전환" 칸의 목록을 눌러 [안 함]을 고른다. [화면 미확인] (노트북이면 "배터리 사용 시"도 같은 방식으로 정한다.)
7. 설정 창을 닫는다.

**4-C. Git 설치** (코드를 받는 데 필요하다. D1 시작 전까지만 하면 된다)

1. 브라우저 주소창에 `git-scm.com`을 입력하고 Enter를 누른다. Git 공식 화면이 보인다.
2. [Download for Windows] 버튼을 누른다. [화면 미확인] 설치 파일이 내려받아진다.
3. 내려받은 설치 파일을 두 번 누른다. 설치 창이 열린다.
4. 선택 화면은 기본값 그대로 두고 [Next]를 누르며 넘어간다. [화면 미확인] 마지막에 [Install] 버튼이 보인다.
5. [Install]을 누른다. 진행 막대가 찬다.
6. [Finish]를 누른다. [화면 미확인]
7. 공통 A로 명령 프롬프트를 연다.
8. `git --version`을 입력하고 Enter를 누른다. `git version 2.x.x`가 보인다.

#### D1 끝: Windows 작업 스케줄러로 30분마다 자동 실행하기

화면 이름은 모두 [화면 미확인]이다(Windows 버전·언어에 따라 다를 수 있다). 따라 하다 다른 곳이 있으면 채팅에 알려 주고, 총괄이 D0·D1 중 실제 화면에 맞춰 고친다. 아래 `<실행 파일>`은 developer가 D1 끝에 알려 주는 `.bat` 파일의 전체 경로이고, `<프로젝트 폴더>`는 코드가 있는 폴더 경로다.

**수동 시험**

1. 공통 A로 명령 프롬프트를 연다.
2. `<실행 파일>`을 입력하고 Enter를 누른다. 프로그램이 한 번 돌고 "완료"(또는 developer가 정한 마지막 문구)가 보인다. 오류 문구가 보이면 여기서 멈추고 채팅에 알린다. (키·토큰이 보이는 줄은 가리고 알린다.)

**공통 B. 작업 스케줄러 열기**

1. 키보드의 Windows 키를 누른다. 시작 메뉴가 열린다.
2. `작업 스케줄러`를 입력한다. 검색 결과 맨 위에 [작업 스케줄러]가 보인다. [화면 미확인]
3. Enter를 누른다. 작업 스케줄러 창이 열린다.

**작업 만들기**

1. 공통 B로 작업 스케줄러를 연다.
2. 오른쪽 [동작] 칸의 [작업 만들기...]를 누른다. [기본 작업 만들기]가 아니라 이 항목이다. [화면 미확인] "작업 만들기" 창이 열리고 [일반] 탭이 보인다.
3. [이름] 칸에 `입찰사이클`을 입력한다. [화면 미확인]
4. [사용자가 로그온할 때만 실행]이 선택되어 있는지 본다. 다른 항목이 선택되어 있으면 이것을 누른다. [화면 미확인] (이 항목은 비밀번호를 저장하지 않아도 된다. 대신 PC에 로그온한 상태여야 돈다.)
5. 위쪽의 [트리거] 탭을 누른다. 빈 목록이 보인다.
6. 아래쪽 [새로 만들기...]를 누른다. [화면 미확인] "새 트리거" 창이 열린다.
7. [작업 시작] 칸이 [일정에 따라]인지 본다. 다르면 목록에서 [일정에 따라]를 고른다. [화면 미확인]
8. [설정] 영역의 [매일]을 누른다. [화면 미확인]
9. [시작] 칸의 날짜는 오늘로 두고, 시간 칸에 다음 정각 또는 30분 시각(예: 지금이 14:10이면 14:30:00)을 입력한다. [화면 미확인]
10. [고급 설정] 영역의 [작업 반복 간격] 칸을 체크한다. [화면 미확인] 오른쪽 목록이 활성화된다.
11. [작업 반복 간격] 오른쪽 목록을 눌러 [30분]을 고른다. [화면 미확인] 목록에 [30분]이 없으면 `30분`을 직접 입력한다.
12. [반복 기간] 오른쪽 목록을 눌러 [무기한]을 고른다. [화면 미확인]
13. 맨 아래 [사용] 칸이 체크되어 있는지 본다. 체크가 없으면 체크한다. [화면 미확인]
14. [확인]을 누른다. 트리거 목록에 "매일 ... 30분마다" 같은 줄이 생긴다.
15. 위쪽의 [동작] 탭을 누른다. 빈 목록이 보인다.
16. 아래쪽 [새로 만들기...]를 누른다. "새 동작" 창이 열린다.
17. [동작] 칸이 [프로그램 시작]인지 본다. 다르면 [프로그램 시작]을 고른다. [화면 미확인]
18. [프로그램/스크립트] 오른쪽의 [찾아보기...]를 누른다. 파일 선택 창이 열린다. [화면 미확인]
19. `<실행 파일>`을 찾아 선택하고 [열기]를 누른다. [프로그램/스크립트] 칸에 경로가 채워진다.
20. [시작 위치(옵션)] 칸을 누르고 `<프로젝트 폴더>` 경로를 입력한다. [화면 미확인] (따옴표는 붙이지 않는다.)
21. [확인]을 누른다. 동작 목록에 줄이 생긴다.
22. 위쪽의 [조건] 탭을 누른다. [화면 미확인]
23. (노트북일 때만) [컴퓨터의 AC 전원이 켜져 있는 경우에만 작업 시작] 칸의 체크를 푼다. [화면 미확인]
24. [컴퓨터를 절전 모드 해제하여 이 작업 실행] 칸을 체크한다. [화면 미확인] (절전을 꺼 두었어도 안전장치로 켠다.)
25. 위쪽의 [설정] 탭을 누른다. [화면 미확인]
26. [예약된 시작 시간을 놓친 경우, 가능한 한 빨리 작업 시작] 칸을 체크한다. [화면 미확인] (PC가 꺼져 있다 켜졌을 때 따라잡는 용도다.)
27. [작업이 이미 실행 중이면 다음 규칙 적용] 목록에서 [새 인스턴스를 시작하지 않음]을 고른다. [화면 미확인] (이전 실행이 안 끝났을 때 두 번 도는 것을 막는다.)
28. [작업을 중지할 때까지의 시간] 칸을 체크하고 목록에서 [1시간]을 고른다. [화면 미확인] (멈춰 버린 실행을 정리한다.)
29. [확인]을 누른다. 창이 닫힌다. (암호를 묻는 창이 나오면 PC 로그온 암호를 입력한다. 4번 항목이면 보통 묻지 않는다.)

**확인**

1. 왼쪽의 [작업 스케줄러 라이브러리]를 누른다. [화면 미확인] 가운데 목록에 [입찰사이클]이 보인다.
2. [입찰사이클] 줄을 한 번 눌러 선택한다. 줄이 파랗게 칠해진다.
3. 오른쪽 [동작] 칸에서 [실행]을 누른다. [화면 미확인] 상태가 잠깐 [실행 중]으로 바뀐다.
4. 키보드의 F5를 누른다. 목록이 새로 고쳐진다.
5. 같은 줄의 [마지막 실행 결과] 칸을 본다. "작업을 완전히 마쳤습니다. (0x0)"가 보이면 성공이다. [화면 미확인]
6. 공통 A로 명령 프롬프트를 연다.
7. developer가 알려 준 상태 확인 명령을 입력하고 Enter를 누른다. 방금 시각의 collect_runs 줄이 새로 생긴 것이 보인다.
8. 30~35분 기다린다.
9. 작업 스케줄러에서 F5를 누른다. [입찰사이클] 줄의 [마지막 실행 시간]이 30분 안쪽 시각으로 바뀌어 있다. 이후에도 30분마다 바뀌면 설정이 끝난 것이다.

되돌리기(멈추기): 공통 B -> 왼쪽 [작업 스케줄러 라이브러리] -> [입찰사이클] 줄 오른쪽 클릭 -> [사용 안 함]. 문제가 생기면 먼저 이렇게 멈춘다. [화면 미확인]

### D2. 조건 매칭 + 묶음 알림 (S1, MVP 핵심, 사용 시작일)

| 항목 | 내용 |
|---|---|
| 할 일 | 조건(설정 파일) 해석·매칭, 대기 목록(pending), 마감 임박 판정, 계정별 발송 시각 2~3개(30분 단위), 묶음 메시지 만들기(건수 상한 50, 요약 줄, 메시지 분할), 텔레그램 어댑터, **사이클 맨 앞의 텔레그램 새 메시지 확인(getUpdates)과 `/start 연결코드` 처리(chat id 저장, "연결됐습니다" 답, 처리 위치 저장)**, 연결 코드 발급, 사이클 중복 실행 잠금, 실패 재시도, 정정공고 라벨, 만료(expired) 처리, 백필 공고 알림 제외, PC가 꺼져 있던 동안 쌓인 묶음 합쳐 보내기 |
| 담당 | developer (텔레그램 스킬이 필요하면 skill-scout) |
| 작업량 | 약 4일 |
| 완료 기준 | 하루 2~3번 지정 시각에 묶음이 온다 / 마감 임박 공고가 묶음 맨 위에 마감 빠른 순으로 나온다 / 같은 공고가 두 번 오지 않음 / 테스트 계정 2개가 서로 다른 조건·발송 시각으로 각자 다른 묶음을 받는다 / 전 업종 조건에서도 건수 상한·요약 줄이 동작한다 / 연결 코드가 틀리면 chat id가 저장되지 않는다 / `/start 코드` 후 30분 안에 "연결됐습니다"가 온다 / 백필로 받은 과거 공고는 묶음에 나오지 않는다 |

D2 완료일이 **사용 시작일**이다. 이 날부터 한 달 뒤가 판매 결정 시점이다.

### VPS 이전 (D2 직후, 사용 시작일 직후, S1)

기본 시점은 D2 완료 직후(달력 약 2주차 말, 결정 "1~2주 뒤"에 해당). D1이 일찍 끝나 PC에서 며칠 이상 안정적으로 돌았다면 D2 중에도 가능하다. VPS 업체는 사용자가 고른다(월 약 5천~3만 원 [추정]). VPS 업체 화면과 서버 OS 명령은 업체·OS마다 달라, 업체를 고른 뒤 developer가 그 화면에 맞춘 안내 한 장을 따로 준다. 아래는 그 전에 흐름을 잡는 기준 단계이며 VPS 쪽은 Ubuntu 서버(Linux)를 가정한다 [추정]. 모든 버튼·메뉴 이름은 [화면 미확인]이다.

| 항목 | 내용 |
|---|---|
| 담당 | 사용자(VPS 신청, 접속 정보 보관) + developer(설치·확인) |
| 작업량 | 0.5~1일 |
| 완료 기준 | VPS에서 이틀 연속 수집·발송이 돌고, 중복 알림·한도 초과·로그 키 노출이 없음 / PC 쪽 작업 스케줄러가 꺼져 있고 PC의 `.env`와 `C:\g2b-secrets\keys.env` 사본이 삭제됨 |

이전 절차 (한 단계에 행동 하나, 위에서부터 차례로. 대괄호는 어느 컴퓨터에서 하는지):

PC 쪽 정지와 백업

1. [PC] 공통 B로 작업 스케줄러를 연다.
2. [PC] 왼쪽 [작업 스케줄러 라이브러리]를 누른다. 목록에 [입찰사이클]이 보인다.
3. [PC] [입찰사이클] 줄을 오른쪽 클릭한다. 메뉴가 열린다.
4. [PC] [사용 안 함]을 누른다. 상태 칸이 [사용 안 함]으로 바뀐다.
5. [PC] F5를 눌러 새로 고친다. 상태가 [실행 중]이 아니고 [사용 안 함]이다. (이전 실행이 아직 돌고 있었다면 [사용 안 함]만 보일 때까지 기다렸다가 다시 F5를 누른다.)
6. [PC] 공통 A로 명령 프롬프트를 연다.
7. [PC] developer가 알려 준 상태 확인 명령을 입력하고 Enter를 누른다. 마지막 성공 시각이 보인다.
8. [PC] 그 시각을 메모해 둔다. 이전 뒤 이어받는 기준이다. (비밀값이 아니므로 아무 메모에 적어도 된다.)
9. [PC] developer가 알려 준 백업 명령을 입력하고 Enter를 누른다. SQLite 백업 기능으로 백업 파일이 만들어진다. 파일을 그냥 복사하지 않는다(WAL 모드라 복사본이 깨질 수 있음).
10. [PC] `dir`로 백업 파일 줄을 본다. 파일 크기가 0이 아닌 것을 확인한다. (`dir <백업 폴더>`처럼 폴더를 함께 입력한다.)

VPS 준비

11. [브라우저] 사용자가 고른 VPS 업체 사이트를 연다. 업체 첫 화면이 보인다.
12. [VPS 업체 사이트] 로그인하거나 가입한다. 내 계정 화면이 보인다.
13. [VPS 업체 사이트] 가장 낮은 사양(메모리 1~2GB급 [추정])의 서버 상품을 고른다. 운영체제는 Ubuntu 최신 LTS를 고른다 [추정]. 주문 요약이 보인다.
14. [VPS 업체 사이트] 결제하고 서버를 만든다. 접속 주소(IP)와 접속 계정 안내가 나온다.
15. [PC] 업체가 준 접속 비밀번호 또는 키 파일을 `C:\g2b-secrets`에 저장한다. 채팅에는 붙이지 않는다.
16. [PC] 공통 A로 명령 프롬프트를 연다.
17. [PC] `ssh 계정@서버주소`를 입력하고 Enter를 누른다. 처음이면 "계속 연결할까요?" 같은 물음이 나온다.
18. [PC] `yes`를 입력하고 Enter를 누른다. 비밀번호를 묻는 줄이 나온다.
19. [PC] 접속 비밀번호를 입력하고 Enter를 누른다. (입력 글자는 화면에 안 보이는 것이 정상이다.) 서버의 명령 입력줄이 보인다.
20. [VPS] developer가 준 "Python 설치" 명령을 입력하고 Enter를 누른다. 설치가 끝나고 입력줄이 돌아온다.
21. [VPS] developer가 준 "코드 받기" 명령(git에서 받음)을 입력하고 Enter를 누른다. 프로젝트 폴더가 생긴다.
22. [VPS] 시험 실행 명령을 입력하고 Enter를 누른다. 프로그램이 오류 없이 시작된다. (아직 키가 없다는 안내가 나오는 것은 정상이다.)

비밀값과 데이터 옮기기

23. [VPS] `nano .env`를 입력하고 Enter를 누른다. 빈 편집 화면이 열린다.
24. [PC] `C:\g2b-secrets`의 키 파일(또는 `.env`)을 메모장으로 연다. 키 줄이 보인다.
25. [PC] 서비스키 줄 하나를 끌어 선택하고 Ctrl+C를 누른다.
26. [PC -> VPS] 서버 창을 눌러 마우스 오른쪽 버튼으로 붙여 넣는다. 줄이 나타난다. (이 창과 키는 채팅에 붙이지 않는다.)
27. [PC] 같은 방식으로 봇 토큰 줄도 복사해서 서버 창에 붙여 넣는다. 줄이 추가된다.
28. [VPS] Ctrl+O를 누르고 Enter를 누른다. 저장되었다는 표시가 나온다.
29. [VPS] Ctrl+X를 누른다. 입력줄로 돌아온다.
30. [PC] 새 명령 프롬프트(공통 A)에서 `scp 백업파일 계정@서버주소:경로`를 입력하고 Enter를 누른다. 전송이 100%로 끝난다.
31. [VPS] developer가 준 "백업 복원" 명령을 입력하고 Enter를 누른다. 복원이 끝났다는 문구가 나온다.
32. [VPS] 상태 확인 명령을 입력하고 Enter를 누른다. 공고 건수가 PC에서 센 건수와 같다.

시험과 자동 실행

33. [VPS] 수집을 한 번 수동 실행한다. collect_runs에 성공 줄이 생기고, 마지막 성공 시각 이후가 6일 이하 조각으로 따라잡힌다.
34. [VPS] 테스트 계정으로 묶음 발송을 한 번 실행한다. 텔레그램에 묶음이 온다. PC는 꺼져 있으므로 중복이 없다.
35. [VPS] `crontab -e`를 입력하고 Enter를 누른다. 편집 화면이 열린다.
36. [VPS] 마지막 줄에 `*/30 * * * * <run_cycle 실행 명령>`을 입력한다. (실행 명령은 developer가 준다. 한 줄이다.)
37. [VPS] 저장하고 나간다. "새 crontab을 설치했다"는 문구가 나온다.
38. [VPS] 30분 뒤 상태 확인 명령을 입력하고 Enter를 누른다. 자동 실행 기록이 새로 생겨 있다.

이틀 뒤 정리

39. [VPS] 이틀 뒤 호출 카운터(api_usage)를 확인한다. 하루 호출이 경고 임계치 700 미만(또는 예상 범위)이다.
40. [텔레그램] 이틀 동안 온 묶음을 훑어본다. 같은 공고가 두 번 오지 않았다.
41. [VPS] 로그 파일에서 서비스키 앞부분을 검색한다. 0건이다.
42. [PC] `C:\g2b-secrets\keys.env`를 삭제한다. 파일이 사라진다.
43. [PC] 프로젝트 폴더의 `.env`를 삭제한다. 파일이 사라진다.
44. [PC] 공통 B로 작업 스케줄러를 열고 [입찰사이클]을 오른쪽 클릭해 [삭제]를 누른다. 목록에서 사라진다. (되돌릴 가능성이 있으면 삭제 대신 [사용 안 함]으로 둔다.)
45. [텔레그램] 다음 발송 시각에 묶음이 계속 온다. VPS가 혼자 돌고 있는 것이다.

주의: 같은 서비스키·봇 토큰을 PC와 VPS가 동시에 쓰면 한도가 이중으로 소모되고 알림이 두 번 간다. 1~5단계(PC 정지)를 반드시 먼저 한다. 문제가 생기면 PC의 [입찰사이클]을 [사용]으로 되돌리고 VPS의 crontab 줄을 지워 멈추는 순서로 되돌린다(데이터는 6일 조각으로 따라잡힘).

### 증량 신청 (별도, 판매 결정과 무관, D1~D3 사이)

결정: 판매 준비는 한 달 뒤에 정하지만 호출 한도 증량 신청은 일찍 한다. 증량 신청은 비용이 들지 않고 판매하지 않아도 필요할 수 있기 때문이다.

| 항목 | 내용 |
|---|---|
| 먼저 알아야 할 것 | D0 확인 7번: 승인 방식(자동인지 심사인지)·소요시간·증량 수치, 활용사례 등록에 필요한 것(웹 주소, 화면 캡처, 사업자 여부, 개인 사용도 가능한지). 모두 미확인이다 |

| 작업량 | 반나절 |
| 완료 기준 | 신청 결과(승인 방식·소요시간·늘어난 수치)를 spec 6-2에 기록 |

활용사례는 사실대로 적는다("나라장터 입찰 공고 알림 서비스, 현재 개인 사용"). 판매 계획을 확정된 것처럼 쓰지 않는다. 신청 화면의 번호 단계는 D0 확인 7번 결과로 화면 이름이 확인된 뒤, 이 시점 직전에 총괄이 한 단계 한 행동으로 써서 준다(지금은 화면을 몰라 쓰지 않는다).

## 유출 시 대처 (서비스키 / 봇 토큰 각각, 한 단계에 행동 하나)

화면 문구는 모두 [화면 미확인]이다. 데이터포털의 재발급 기능 이름은 미확인이라 D0에서 실제 화면을 보고 이 절을 고친다. "스케줄을 끈다/켠다"는 PC에서는 공통 B의 작업 스케줄러에서 [입찰사이클]을 [사용 안 함]/[사용]으로 바꾸는 것이고, VPS에서는 crontab 줄 앞에 `#`을 붙이거나 지우는 것이다.

서비스키가 로그·git·채팅에 노출되었을 때:

1. 수집·발송 스케줄을 끈다. 이후 호출이 멈춘다.
2. 브라우저로 data.go.kr을 열고 로그인한다. 오른쪽 위에 내 이름이 보인다.
3. [마이페이지]를 누른다.
4. 개발계정(활용 현황) 목록에서 해당 서비스 이름을 누른다. 인증키가 보인다.
5. 인증키 재발급(또는 갱신) 버튼을 누른다. 새 키가 나온다. 재발급 버튼이 없으면 활용신청을 삭제하고 다시 신청해 새 키를 받는다 [추정, D0에서 확인].
6. 새 Encoding 키를 복사해 `.env`의 옛 키 줄을 바꾸고 저장한다.
7. 새 Decoding 키를 복사해 `.env`의 옛 키 줄을 바꾸고 저장한다.
8. 로그 파일에서 옛 키 앞부분을 검색한다. 나오면 해당 로그 파일을 지운다.
9. 백업 파일에서 옛 키 앞부분을 검색한다. 나오면 해당 백업 파일을 지운다.
10. git 이력에서 옛 키 앞부분을 검색한다. 나오면 키 재발급(5단계)이 이미 끝났는지 확인하고, 이력 정리는 총괄에게 맡긴다.
11. 스케줄을 다시 켠다.
12. 첫 호출이 정상 응답(오류 없음)으로 기록되었는지 상태 확인 명령으로 본다.

봇 토큰이 노출되었을 때:

1. 수집·발송 스케줄을 끈다.
2. 텔레그램에서 BotFather 대화창을 연다.
3. `/revoke`를 입력하고 전송한다. 내 봇 목록이 나온다.
4. 해당 봇을 누른다. 새 토큰이 표시되고 옛 토큰은 쓸 수 없게 된다.
5. 새 토큰을 복사해 `.env`의 옛 토큰 줄을 바꾸고 저장한다.
6. 로그·백업·git 이력에서 옛 토큰을 검색해 지운다(이력 정리는 총괄에게 맡긴다).
7. 스케줄을 다시 켠다.
8. 테스트 메시지가 도착하는지 본다.

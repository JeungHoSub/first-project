# 책 읽어주기 유튜브 — 로드맵 초안

작성: planner / 기준일 2026-11-12 / 상태: 초안 (사용자 결정 대기)

> 결정 대기 4개 항목(목소리, 분야, 길이, 첫 책)은 추천안을 **[가정]** 으로 두고 짠 계획이다. 답이 달라지면 해당 단계만 수정한다. 기간은 사용자 검토 대기 시간을 뺀 작업 기준 추정이다. 상세는 spec.md 참고.
> 모든 단계의 끝은 reviewer 1차 검수 → `review/QUEUE.md` → 사용자 검토다.

---

## 단계 0. 기획 확정 (약 2~3일)
- **목표**: 사용자 결정 4개 확정, 위험 기준 합의, 파일럿 착수 조건 정리
- **산출물**
  - brief.md "확인 필요"에 선택지 반영 및 사용자 답 기록, spec.md 확정본
  - 채널 이름·핸들 중복 확인 결과
  - 저작권·YouTube 정책 원문 재확인 메모(법령 조문, 수익 창출 정책, 일반 TTS의 합성 표기 의무)
  - TTS 서비스 비교표(요금, 상업 이용·수익화 약관, 한국어 품질)
  - `rights.md` 뼈대
- **담당**: planner(spec/roadmap 갱신), researcher(정책 원문·TTS·채널명 조사), 총괄(사용자 질의), skill-scout(필요 시 TTS·ffmpeg 영상 제작 스킬 초안)
- **완료 기준**: 사용자가 목소리·분야·길이·첫 책을 답했고 spec.md의 [가정] 표시가 확정으로 바뀜. TTS 후보 1개 선정. 정책 원문 확인 항목이 "확인됨/미확인"으로 분류됨

## 단계 1. 파일럿 1편 (약 1주)
- **목표**: 고전 1편(『명상록』 [가정], 약 17분)을 끝까지 만들어 파이프라인 전체를 한 번 통과. 완성도가 아니라 "돌아가는지"와 "듣기 좋은지" 검증
- **산출물** (`outputs/ep001/`)
  - `source.md`(직접 번역 원문·판본·출처), `rights.md` ep001 항목
  - `script.md`(약 5,100자, 꼭지 4개, 쇼츠 후보 2~3개 표시 `shorts-candidates.md`)
  - `review.md`
  - `audio.mp3`, `audio-timing.json`
  - `video.mp4`, `subtitles.srt`, `thumbnail.png`
  - `metadata.json`(AI 음성 표기 포함)
  - 업로드(**수동, 비공개 또는 사용자 승인 후 공개**)와 결과 메모
  - 파이프라인 회고 메모(걸린 시간, 막힌 곳, 비용 실측)
- **담당**: researcher(원문·저작권 확인) → content-writer(대본, 번역 초벌, 메타데이터) → reviewer(검수) → media-producer(TTS·영상) → 총괄(사용자 검토 요청)
- **완료 기준**
  - reviewer 체크리스트(일상 장면, 원문 비중 25~30% 이내, 듣기 품질, 복습, 변주) 전부 통과
  - 사용자가 영상을 듣고 "딱딱하지 않다"에 동의(style-guide 선호 기준)
  - 번역은 사람 검수 완료, `rights.md` 기록 완료
  - YouTube Studio에서 업로드 시 합성 표기 질문 응답 기준을 확인해 기록
  - 실측 비용(TTS 포함)과 제작 소요시간 기록

## 단계 2. 첫 5편 (약 3~4주)
- **목표**: 고전 3 + 최신 2를 만들어 두 라인을 모두 검증하고, 변주 규칙·인용 규칙이 실제로 지켜지는지 확인. 주 1편 공개 리듬 확립
- **산출물**
  - ep002~ep005 일체(단계 1과 같은 파일 구성)
  - 최신 책 라인 첫 회: 인용 상한(3문장·3% 제안값) 준수 로그
  - 첫 최신 책 확정(research 후보 재확인: 『혼모노』, 『트렌드 코리아』 등, 출간 연도·순위 최신 확인 후)
  - 대본·영상 템플릿 정리(재사용용), 변주 체크 기록
  - 쇼츠 후보 파일과 shorts-auto 프로젝트 간 입력 규격 합의안, 쇼츠 시험 추출 1~2개
  - 단계 2 회고: 조회·시청 지속 시간 등 YouTube Studio 지표(공개 후), 비용·시간 누적
- **담당**: researcher(최신 책 선정·저작권) → content-writer → reviewer → media-producer → 총괄. shorts-auto 연동은 총괄이 조율(shorts-auto 담당 에이전트와)
- **완료 기준**
  - 5편 모두 reviewer 통과 및 사용자 승인, `rights.md` 5건 완비
  - 최신 회차에 줄거리·결말 공개, 장별 요약, 표지 사용이 없음
  - 회차 간 구성이 같은 틀의 복제로 보이지 않는다는 reviewer 판단(제목·훅·꼭지 수·비유 변주 확인)
  - 쇼츠 후보 추출 방식이 shorts-auto와 합의됨
  - 계속할지·주 2회로 늘릴지·목소리 혼합으로 갈지 사용자 결정

## 단계 3. 자동화 (약 3~4주, 병행 가능)
- **목표**: 반복 작업(TTS 호출, 영상 합성, 메타데이터 생성, 업로드)을 스크립트화해 사람은 **기획 선택·검토·승인**에만 집중. 주 2회 운영 기반
- **산출물**
  - `projects/shared/` 업로드 모듈(YouTube Data API v3, 예약 업로드, 중복 방지, `upload-log.csv`). 쇼츠·음악 프로젝트와 공유
  - 책 채널용 파이프라인 스크립트: `script.md` → TTS → ffmpeg 영상 → `metadata.json` 생성(`projects/book-podcast/` 또는 shared)
  - 승인 게이트: `review/QUEUE.md` 승인 확인 후에만 업로드
  - 쇼츠 자동 추출 연동(`shorts-candidates.md` → shorts-auto)
  - API 감사 신청 여부 결정과 결과(미감사 시 비공개 고정 가능), 할당량 운영 메모
  - 운영 가이드(`outputs/ops.md` 등)와 파이프라인 오류 처리
- **담당**: developer(스크립트·업로드 모듈), media-producer(영상·TTS 템플릿 검증), content-writer·reviewer(자동화 후에도 대본 검수 유지), 총괄(shared 모듈 조율)
- **완료 기준**
  - 승인된 대본 1편으로 TTS부터 업로드까지 사람 수작업 없이(승인 클릭 제외) 완주
  - 재시도·중복 방지·로그 동작 확인, `client_secret.json`·토큰이 git에 없음
  - 업로드 공개 여부가 정책(감사)과 일치. 공개 불가 시 수동 업로드 유지 방침 명시
  - 자동화 후에도 reviewer 검수·rights.md 기록이 생략되지 않음(자동 통과 금지)
  - 주 2회 운영이 2주 이상 문제 없이 돌아감

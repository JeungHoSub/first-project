# 매직고스톱 앱 출시 절차 조사

- 작성: researcher / 확인 날짜: 2026-11-17
- **일반 정보이며 법률 자문이 아니다. 저작권·사행성·개인정보·게임산업법 관련 확정 판단은 변호사·게임물관리위원회(게임위) 등 전문가 확인이 필요하다.**

## 한 줄 결론

앱 포장은 **Capacitor**(웹 화면을 그대로 안드로이드·iOS 앱으로 감싸는 도구)가 가장 맞다. 지금처럼 엽전이 현금과 무관하고 유료 결제가 없으면 출시 절차는 가볍다. **유료 뽑기권(현금 결제)을 붙이는 순간 한국 법(확률 공개·웹보드게임 규제)과 스토어 결제 정책이 한꺼번에 걸리므로, 1차 출시는 무료 + 결제 없음으로 하고 결제는 별도 단계로 분리하는 것을 권한다.**

## 이 문서의 근거 수준 (먼저 읽어 주세요)

이번 조사 환경에서는 일부 공식 사이트(Google Play Console 도움말 `support.google.com`, 법제처 `law.go.kr`, 게임위 `grac.or.kr`, Capacitor 공식 문서)에 접속이 막혀 **원문을 직접 열어보지 못했다.** 그래서 표기를 이렇게 나눴다.

- **[공식 확인]** 이번에 공식 페이지를 직접 열어 확인함
- **[검색 요약]** 검색 결과 요약으로 확인(공식 링크는 달았지만 원문은 못 열어봄)
- **[보도/블로그]** 언론·업체 글. 참고용이며 반드시 공식 원문으로 재확인
- **[불확실]** 근거가 약함 — 출시 직전에 반드시 확인

공식 원문은 사용자가 직접 열거나, 세션 네트워크 설정에서 위 도메인을 허용해 주면 다시 확인할 수 있다.

## 1. 웹앱을 앱으로 만드는 방법 비교

| 방식 | 설명 | 장점 | 단점 |
|---|---|---|---|
| PWA | 홈 화면에 추가하는 웹앱. 스토어 등록 없음 | 비용 0, 제일 쉬움 | iOS에서 설치·푸시 등이 약하고, 스토어에 노출 안 됨. "앱 출시" 목표와 안 맞음 |
| TWA (Trusted Web Activity) | 크롬이 웹을 전체 화면으로 띄우는 안드로이드 전용 방식 | 안드로이드는 간단, 용량 작음 | **안드로이드 전용** (iOS 불가). 웹과 앱이 같은 개발자 소유임을 Digital Asset Links로 증명해야 하고, 앱이 웹의 쿠키·localStorage에 직접 접근 못 함 |
| **Capacitor** | 웹 화면을 네이티브 앱 껍데기(WebView)에 넣고 필요하면 네이티브 기능(결제·푸시 등) 플러그인 사용 | **안드로이드·iOS 한 코드베이스**, 단일 HTML/Vite와 궁합 좋음, 앱 안에 웹 파일을 포함해 오프라인 동작, 인앱결제 플러그인 연결 가능 | iOS 빌드엔 Xcode(=Mac)가 필요(클라우드 빌드로 우회 가능) |
| 기타(Cordova, React Native 등) | — | — | 이미 만든 웹 화면을 다시 짜거나 구형 도구라 이득이 적음 |

### 추천: Capacitor

이유
1. 목표가 안드로이드+iOS 둘 다이고, TWA는 안드로이드뿐이다.
2. 이미 TypeScript + Vite 웹앱이라 `dist` 폴더를 그대로 앱에 넣으면 된다(엔진·화면 분리 구조와 잘 맞음).
3. 나중에 인앱결제가 필요하면 네이티브 플러그인으로 연결할 수 있다. (TWA/PWA는 결제 연결이 제한적)
4. **Apple 심사 대비**: Apple은 "웹사이트를 그냥 감싼 앱"을 4.2(최소 기능)로 거절할 수 있다고 명시한다. 게임은 앱 안에 자체 포함된 오프라인 콘텐츠이고 사운드·연출·저장 기능이 있어 통상 문제가 적지만, 단순 웹사이트 링크처럼 보이지 않게 **웹 파일을 앱에 포함**해야 한다.
   - 근거: [Apple 앱 심사 가이드라인 4.2](https://developer.apple.com/app-store/review/guidelines/) [공식 확인] — "Apps should offer features, content, and UI beyond a repackaged website"
5. TWA 자체 특성 근거: [Android Developers, Trusted Web Activity](https://developer.android.com/develop/ui/views/layout/webapps/trusted-web-activities) [공식 확인]

Capacitor 자체 요구사항(Xcode/Android Studio)은 공식 문서 [capacitorjs.com/docs](https://capacitorjs.com/docs/getting-started)에서 확인해야 한다 [미확인 — 접속 불가]. 업계 상식상 iOS 빌드는 Xcode 필요.

## 2. Google Play 등록 단계

### 2-1. 개발자 계정
| 항목 | 내용 | 근거 |
|---|---|---|
| 등록비 | 1회 25달러 | [보도/블로그] 공식 문서는 못 열어봄. [Play Console 안내](https://play.google.com/console/about/)에서 확인 |
| 본인 확인 | 개인 계정은 정부 발급 신분증 등으로 본인 확인(소요 1~7일이라는 블로그 글 있음). 조직 계정은 D-U-N-S 번호 필요 | [보도/블로그] [불확실] 한국 기준 절차·소요는 가입 화면에서 확인 |
| 개인 vs 조직 | **개인 계정**이 가장 쉽다. 조직 계정은 사업자·D-U-N-S 필요. 아래 비공개 테스트 요건은 개인 계정에만 적용 | [Play Console 도움말: 신규 개인 계정 테스트 요건](https://support.google.com/googleplay/android-developer/answer/14151465) [검색 요약] |
| 개인 계정 공개 정보 | 개인정보(이름·주소 등)가 스토어에 공개되는지는 이번에 확인 못 함 | [불확실] 가입 시 안내 문구 확인 |

### 2-2. 신규 개인 계정의 비공개 테스트 요건 (중요, 출시 일정에 직접 영향)
- 2023-11-13 이후 만든 **개인** 개발자 계정은 프로덕션(정식 출시) 전에 **비공개 테스트(closed test)를 해야 한다.**
- 프로덕션 신청 시점에 **테스터 12명 이상이 최근 14일 이상 연속으로** 테스트에 참여(opt-in) 상태여야 한다.
- 충족하면 "신청 자격"이 생길 뿐 자동 승인은 아니다(심사 있음).
- 근거: [Google Play Console 도움말 14151465](https://support.google.com/googleplay/android-developer/answer/14151465) [검색 요약, 2026-11-17 확인], 12명 기준은 2024-12에 20명에서 완화됐다는 블로그 설명 [보도/블로그].
- 의미: 정식 출시 **최소 2주 + 테스터 12명 모집**이 필요하다. 개인 공유용으로 만든 지인들이 테스터가 될 수 있으니 지금부터 모아 두면 좋다. 조직 계정은 면제라는 글이 있으나 [불확실].

### 2-3. 앱 서명 · AAB
- 새 앱은 **AAB(Android App Bundle)** 형식으로 올린다. **Play 앱 서명(Play App Signing)**을 쓰면 Google이 배포용 키를 보관하고, 우리는 "업로드 키"만 관리한다. (일반적인 현행 절차 — 이번에 도움말 원문은 못 열어봄 [불확실])
- 업로드 키(키스토어 파일·비밀번호)는 **분실하면 곤란**하므로 사용자가 직접 보관해야 한다.
- **타깃 API 수준**: 2026-08-31부터 신규 앱·업데이트는 **Android 16(API 36) 이상** 타깃이어야 한다. 근거: [Android Developers - Target API level requirements](https://developer.android.com/google/play/requirements/target-sdk) [공식 확인, 2026-11-17]. Capacitor 최신 버전을 쓰면 대체로 맞춰진다 [불확실, 버전 확인 필요].

### 2-4. 스토어 등록정보
앱 이름, 짧은 설명(80자), 상세 설명(4000자), 아이콘 512x512, 피처 그래픽 1024x500, 폰 스크린샷 최소 2장 등. (일반적 규격 — 정확한 현행 규격은 Play Console 화면에서 확인 [불확실])

### 2-4b. 콘텐츠 등급(IARC)과 한국
- Play Console의 등급 설문(IARC)을 작성하면 지역별 등급이 나온다. 한국은 게임위가 지정한 **자체등급분류사업자**(구글·애플 등)를 통해 게임 등급이 부여되는 구조다(아래 4절).
- 설문에 "도박 요소/가상 도박" 문항이 있다. 고스톱은 **도박을 시뮬레이션하는 카드게임**이므로 높은 연령 등급이 나올 수 있다 [불확실, 설문 답에 따라 달라짐].

### 2-5. 데이터 보안 양식 · 개인정보처리방침 · 타깃 연령
- **개인정보처리방침 URL은 필수**로 입력해야 한다(공개 웹주소 필요 — GitHub Pages 등에 호스팅 가능). [일반 절차, 도움말 원문 미확인]
- **데이터 보안(Data safety) 양식**: 앱이 수집·공유하는 데이터를 신고한다. 계정·서버 없이 기기 안에만 저장하면 "수집 안 함"에 가깝지만, **광고·분석 SDK를 넣으면 신고 항목이 늘어난다.** [일반 절차, 미확인]
- **타깃 연령**: "13세 미만 포함" 여부를 선택한다. 어린이를 포함하면 가족 정책 등 추가 요건이 붙으므로, 고스톱은 **성인/청소년 대상으로 설정**하는 것이 일반적으로 안전 [불확실].
- **뽑기(랜덤 아이템) 확률 공개**: Google Play 정책은 2019년부터 구매로 랜덤 아이템을 받는 앱에 **구매 전 확률 공개**를 요구한다. 근거: [Fenwick 해설(2019)](https://fenwick.com/insights/publications/google-play-now-requires-disclosure-of-loot-box-odds) [보도/해설, 2019년 자료 — 현행 문구는 Play 정책 센터에서 재확인].

## 3. Apple App Store 등록 단계

### 3-1. 개발자 프로그램·장비
- 비용: **연 99달러**(현지 통화 환산). 개인/조직 모두 가입 가능, 가입 시 Apple이 신원 확인. 근거: [Apple Developer Program - 포함 내용](https://developer.apple.com/programs/whats-included/) [공식 확인, 2026-11-17]. 개인은 이름이 판매자로 공개된다는 블로그 설명이 있다 [보도/블로그]. 조직은 D-U-N-S 번호 필요하다는 설명이 일반적이나 이번엔 공식 확인 못 함 [불확실].
- **Mac/Xcode**: 2026-04-28부터 App Store Connect 업로드는 **Xcode 26 이상, iOS 26 SDK**로 빌드해야 한다. 근거: [Apple - Upcoming Requirements](https://developer.apple.com/news/upcoming-requirements/) [공식 확인, 2026-11-17]. 즉 **Mac(또는 Mac 클라우드 빌드)이 사실상 필수**다.
- **Mac이 없을 때 대안** (모두 대안일 뿐, 각 서비스의 현재 조건·가격은 미확인):
  - Apple Developer Program에 **Xcode Cloud(월 25 컴퓨팅 시간) 포함** [공식 확인] — 단, 초기 설정에 Xcode가 필요해 Mac 없이 가능한지는 [불확실]
  - GitHub Actions의 macOS 러너, Bitrise, Codemagic 같은 클라우드 CI, Capawesome Cloud, VoltBuilder(Mac 없이 인증서 생성 가능이라 주장) [보도/업체 글, 편향 가능]: [Capacitor CI 비교(업체 블로그)](https://capawesome.io/blog/comparing-ci-cd-platforms-for-ios-apps/)
  - 참고: Ionic Appflow는 신규 판매 종료(기존 고객 2027-12-31까지) [업체 글] — 선택하지 말 것.
  - **iPhone 실기기 테스트·스크린샷용 기기**는 별도로 필요할 수 있다 [불확실].
- **연령 등급**: Apple은 2026-01-31까지 새 연령 등급 설문(신규 체계)에 응답하도록 했다. 근거: 위 Upcoming Requirements [공식 확인]. 설문 항목에 시뮬레이션 도박이 있다고 알려져 있으나 이번에 직접 확인 못 함 [불확실].

### 3-2. 심사 가이드라인 중 관련 조항 (모두 [공식 확인], 2026-11-17)

| 조항 | 내용 | 우리에게 의미 |
|---|---|---|
| 3.1.1 | 랜덤 가상 아이템을 **구매**하게 하는 앱(루트박스)은 구매 전 **아이템별 획득 확률**을 공개해야 함. 게임 내 재화는 만료되면 안 되고 복원 수단 필요 | 유료 뽑기권 판매 시 필수. 도감에 확률 공개는 이미 계획됨 |
| 5.3 (5.3.1~5.3.4) | 도박·복권은 가장 엄격히 규제되는 분야. **5.3.3: 실제 돈 도박에 쓰는 재화를 인앱결제로 팔 수 없음.** 5.3.4: 실제 돈 도박·복권은 면허·지역 제한·무료 앱 조건 | 우리 앱은 "실제 돈 도박"이 아니어야 하므로 **엽전의 현금 구매·환전 금지 원칙을 지켜야** 5.3 대상에서 벗어남. 이 해석은 심사자 판단 [불확실] |
| 4.2 | 웹사이트를 단순 포장한 앱은 거절 가능 | 오프라인 포함, 앱다운 기능(저장·사운드·연출) 필요 |
| 2.3 | 메타데이터·스크린샷이 실제 앱과 일치해야 함, 앱 이름 30자 제한 | 스토어 문구 작성 시 준수 |
| 1.3 | 키즈 카테고리 제한 | 키즈 카테고리 선택 금지 |

- 5.3 전문의 "시뮬레이션 도박" 문구는 이번에 직접 확인하지 못했다. 카드 도박을 모사한 게임이 별도 연령 등급(높은 등급)을 받는지는 위 연령 설문에서 결정된다 [불확실].
- 심사 노트에 "현금 결제·환전·상금 없음, 가상 재화는 게임 내 승리로만 획득"을 명시할 것을 권한다(권장 사항, 공식 요구 아님).

## 4. 한국 규제

> 이 절은 **가장 불확실성이 크다.** 법제처·게임위 원문을 열지 못했고 대부분 언론 기사 기반이다. 출시 전에 게임위(고객센터)·변호사 확인을 권한다.

### 4-1. 게임물 등급분류와 자체등급분류사업자
- 게임물관리위원회가 등급분류를 하지만, **문체부 장관이 지정한 자체등급분류사업자**(구글, 애플, 삼성전자, 원스토어 등)는 게임위와 협약한 기준에 따라 **스스로 등급을 매길 수 있다.** 구글 플레이·앱스토어 모바일게임은 마켓의 등급 설문을 통해 등급이 부여되고 게임위는 사후관리한다. 제도는 2017-01-01 시행. 근거: [MTN 뉴스(2022)](https://news.mtn.co.kr/news-detail/2022062815071131075) [보도, 2022년], [ZDNet(2021)](https://zdnet.co.kr/view/?no=20210104110646) [보도, 2021년, 구글·애플 포함 9개 사업자]
- 따라서 **스토어 설문(구글 IARC, 애플 연령 설문)을 정직하게 작성하면 별도 게임위 등급분류 신청 없이 출시되는 구조**로 이해된다. 단 이는 **일반 게임**의 경우이고, 아래 웹보드게임 해당 여부에 따라 달라질 수 있다 [불확실].
- 사후관리 사례: 게임위는 P2E·NFT 모바일게임 32종(구글 25, 애플 19)의 등급분류를 취소 예정으로 통보했다(2022). 즉 **허위·축소 설문은 등급 취소·삭제 위험**이 있다. 근거: [블록미디어](https://www.blockmedia.co.kr/archives/235916) [보도, 2022년]
- 게임위 공식 안내: [grac.or.kr](https://www.grac.or.kr) [미확인 — 접속 불가]

### 4-2. 웹보드게임 규제 (고스톱 = 대상 게임)
- 게임산업법 체계에서 **고스톱·포커류 웹보드게임**은 별도 규제(결제·이용 한도, 환전 금지 등)를 받는다. 2014년 도입 당시 **1회 이용(손실) 한도 3만원, 월 결제 한도 30만원, 1일 손실 한도 10만원**, 이후 월 결제 한도가 50만원으로 상향됐다는 보도가 있다. 근거: [디지털데일리(2014)](https://www.ddaily.co.kr/page/view/2014022313135810788), [부산일보(2015)](https://mobile.busan.com/view/busan/view.php?code=20151116000281) [보도, 2014~2015년 자료 — **현행 수치 불확실**, 법제처 시행령 별표 확인 필요]
- 2026-02-25자 비즈워치 기사에 웹보드 관련 내용이 있었으나 열어보지 못함: [링크](https://news.bizwatch.co.kr/article/mobile/2026/02/25/0023) [미확인]. **최근 규제 완화 논의가 있었는지 반드시 확인.**
- **현금 결제가 없는 경우(현재 설계)**: 결제 한도 규제는 "게임머니 결제"에 걸리므로 결제가 없으면 해당 부분은 사실상 적용 대상이 아닐 가능성이 높다. 그러나 **고스톱이 웹보드게임으로 분류되는 것 자체**(등급, 본인확인·성인 제한 등 일반 의무)는 결제와 무관하게 남을 수 있다 [불확실 — 가장 중요한 확인 사항].
- **현금 결제가 있는 경우**: 웹보드게임으로서 월 결제 한도·1회/1일 손실 한도·본인 확인 등 의무가 직접 적용된다(5절).
- 한국에서는 "고스톱 앱"이 스토어에 다수 존재(NHN·네오위즈 등 맞고·포커 서비스)하지만 [ceoscoredaily(2024)](https://www.ceoscoredaily.com/page/view/2024022815461712632) 대부분 대형 사업자이며 위 규제를 준수한다. 개인 개발자의 선례는 못 찾았다.

### 4-3. 사행성 판단 기준
- 사행성 게임물 판단의 핵심은 **금전 베팅과 배당(환전 가능한 경제적 가치)** 구조로 알려져 있다 [MTN(2022)](https://news.mtn.co.kr/news-detail/2022062815071131075) [보도]. 현금·환전·현금성 보상이 없는 가상머니만 쓰는 구조(우리 설계)가 사행성 위험을 낮춘다.
- 주의: **엽전을 아이템 뽑기에 쓰고, 그 아이템을 거래·환전할 수 있으면 사행성·환전 문제**가 생긴다. 현 설계는 "귀속 아이템(거래 불가)"이어서 유리. 앞으로도 **거래·선물·경매 기능을 넣지 말 것**.
- 게임위가 사행성을 판정하는 구체적 조문(게임산업법 제32조 등)은 이번에 열어보지 못했다 [불확실].

### 4-4. 확률형 아이템 정보 공개 의무 (2024-03-22 시행)
- 개정 게임산업법에 따라 2024-03-22부터 **확률형 아이템의 종류·확률 정보 공개가 의무**다. 문체부가 2024-02-19 해설서를 배포했고, 확률형 아이템을 캡슐형·강화형·합성형(컴플리트 가챠 포함)으로 구분해 유형별 표시사항을 정했다. 광고에도 "확률형 아이템 포함" 문구 표시가 요구된다. 위반 시 시정 및 벌칙 등이 예상된다. 근거: [뉴시스(2024-01-02)](https://www.newsis.com/view/NISX20240102_0002577849), [뉴시스(2024-02-19)](https://mobile.newsis.com/view/NISX20240219_0002630806), [ZDNet(2024-02-22)](https://zdnet.co.kr/view/?no=20240222164405), [정책브리핑 korea.kr](https://www.korea.kr/news/policyNewsView.do?newsId=148926013) [모두 보도/정책브리핑 요약 — 원문 조문 미확인]
- **적용 범위 포인트**:
  - 유상(돈으로) 구매 가능한 확률형 아이템이 핵심. 해설서는 **"직·간접적 유상 구매 아이템"**을 대상으로 본다는 보도가 있다.
  - **엽전을 현금으로 살 수 없고 판에서 이겨서만 얻는다면** "유상 구매"에 해당하지 않을 가능성이 있다. 그러나 **엽전을 나중에 유료 상품으로 팔면 직간접 유상이 된다**. 지금은 대상이 아닐 수도 있으나 확정은 아님 [불확실].
  - **연평균 매출 1억원 이하 중소기업 게임물은 의무 면제**라는 보도가 있다 [보도, 조문 미확인]. 개인·초기 출시는 해당될 수도 있으나, 이것을 믿고 확률 비공개를 하지는 말 것. 스토어 정책(Apple 3.1.1, Google)은 이와 별개로 적용된다.
- **실무 권고**: 지금도 도감에 **35종 전체의 등급별·항목별 확률**을 공개하고, 광고·스토어 설명에 "확률형 아이템 포함" 표기를 넣어 두는 것이 안전하다(법적 의무 여부와 무관하게 비용이 거의 안 듦).

### 4-5. 청소년 이용 등급 가능성
- 고스톱은 화투 도박을 모사하므로 **청소년이용불가(만 18세 미만 이용 불가) 또는 높은 연령 등급**을 받을 가능성이 있다. 웹보드게임은 사행성 우려로 일반적으로 성인 대상으로 서비스된다는 점은 알려져 있으나, 구체적 등급 기준 근거를 못 찾았다 [불확실].
- 같은 기사에서 "사행성 요소가 짙은 게임이 청소년이용불가를 피하는 사례"가 지적됐다 — 설문 작성 기준이 모호하다는 뜻이다 [MTN(2022)].
- 권고: 설문에서 **현금 베팅·환전 없음**을 정확히 답하되, 도박 시뮬레이션 문항은 솔직하게 답한다. 결과 등급이 나오는 대로 따르고(등급 낮추려는 축소 답변 금지) 타깃 연령을 성인으로 둔다.

### 4-6. 사업자 등록 필요 여부
- **무료 + 광고·결제 없음 + 취미/공유**: 수익이 없으면 사업자등록 의무는 보통 없다. 광고(애드몹 등)만 있는 경우 통신판매업 신고 대상이 아니라는 설명이 있다 [업체 블로그].
- **유료 결제를 붙이는 경우**: 계속적·반복적 판매이므로 **사업자등록 + 통신판매업 신고**가 필요해질 가능성이 크다. 간이과세자이거나 직전 연도 거래가 50회 미만이면 신고 면제 가능성이 있으나, PG/마켓 계약 과정에서 신고번호를 요구할 수 있다는 설명이 있다. 근거: [토스페이먼츠 블로그](https://www.tosspayments.com/blog/articles/sales-registration), [Taxly Q&A](https://taxly.kr/qna/143994-개인-사업자-통신판매업-등록) [업체 블로그, 공공기관 자료 아님 — 국세청·관할 지자체에 확인]
- **게임물 유통업/게임제공업 등록**과 모바일 게임 앱 서비스의 관계는 이번에 확인하지 못했다 [미확인].

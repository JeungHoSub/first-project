# 매직고스톱 기획 초안 1차 검수 노트

- 검수 대상: `spec.md`, `roadmap.md`, `rules.md` (2026-11-12 초안)
- 검수: reviewer

## 판정: 조건부 통과

방향과 구조는 brief에 잘 맞고 문서 간 큰 모순도 없다. 다만 엔진 구현 전에 확정해야 할 "규칙 충돌 1건 + 지역 기준이 갈리는 항목 몇 개"가 남아 있어, 아래 질문에 답을 받은 뒤 개발 단계로 넘기는 것을 권한다.

## 1. 잘된 점 (brief 부합)

- 기존 고스톱 그대로 + 매직은 켜고 끄는 확장이라는 원칙이 세 문서에 모두 있다. 두 층 구조, 이벤트 훅, "끄면 같은 시드에서 완전 동일" 자동 테스트까지 일관된다.
- brief "확인 필요" 1~3번(추가 기능 / 플랫폼 / 대전 방식)이 spec 10절에 선택지별 범위·일정·위험·재미로 비교돼 있고, 기본 가정이 추천안(웹, AI 1인용)이다.
- 인원은 2인 맞고로 세 문서가 일치한다. 손패 10 / 바닥 8 / 더미 20, 턴 수 20회 = 더미 20장도 맞아 떨어진다.
- 48장 구성은 정확하다.
  - 광 5(1·3·8·11·12비광), 열끗 9, 띠 10, 피 24(쌍피 2 포함), 합계 48.
  - 쌍피는 11월·12월.
  - 홍단 1·2·3 / 청단 6·9·10 / 초단 4·5·7.
  - 고도리 2·4·8월 열끗. 12월 띠는 단 없음. 국진은 9월 열끗.
  - JSON 예시도 표와 일치한다.
- 예시 판은 카드 중복이 없다. 5월 4장은 5열(바닥) / 5피 a(B 손) / 5피 b(A 손) / 5띠(더미)로 딱 맞고, 3월·9월도 정상이다. 점수 계산(3+3+1=7, ×2×2=28)과 바닥 장수(8장 -> A 획득 후 6장)도 맞다.
- 쪽 / 뻑 / 따닥의 정의(H와 D의 월 일치 + 바닥 장수)는 일반적인 정의와 같고 엔진 로직으로 옮기기 쉽다.
- 사행성 대응이 명시돼 있다(rules 머리말, spec 9절, roadmap 위험 메모). 현금·환전·결제·랭킹 보상 금지, "현금 가치 없음" 문구, 출시 전 등급 조사가 들어 있다.
- 코드는 JSON 데이터와 한두 줄 의사코드뿐이라 허용 범위 안이다.
- 문체는 한국어에 읽기 쉬운 편이고 표 위주라 훑어보기 좋다.

## 2. 직접 고친 것 (rules.md, 모두 사소한 오류)

1. 머리말 "3인 고스톱과의 차이는 4장에" -> "2절 표에" (4절은 먹기 판정 요약이다).
2. 1절 "쌍피 2장(4점 상당)" -> "(피 4장 상당)". 점수가 아니라 장수 개념이다.
3. 3.2절 4번 "고/스톱 선택(5.5절)" -> "(5.2절)". 5.5절은 박이다.
4. R19 근거 "3.2절" -> "2절". 선 결정은 2절 5번에 있다.
5. 9절 "1~8장의 기본 규칙" -> "1~8절".
6. 예시 판 턴 1 "3피+3띠를 먹는 중" -> "3피+3띠가 짝 (잠정 처리)". 뜻이 불분명한 표현이었다.

## 3. 수정 제안 (판단이 필요해 고치지 않음)

### 3-1. [중요] 피박 기준이 문서 안에서 충돌
- 5.5절 표는 패자 피 "1~5장"이다. 즉 0장은 제외다.
- R05 기본값은 "<=5장, 0장 포함"이다.
- 엔진 개발자가 어느 쪽을 따를지 알 수 없다. 둘 중 하나로 통일해야 한다.
- 이 기준은 지역마다 갈린다. "0장은 피박 아님" 하우스룰도 있고, 5장 이하에 0장을 포함하는 앱도 있다. 어느 쪽이 더 흔한지는 내 지식으로 단정하지 못했고, 사용자 확인이 필요하다.

### 3-2. [중요] 멍박(멍따) 기본값이 일반적인 설과 다름
- 흔히 말하는 멍따는 "승자 열끗 7장 이상이면 점수 x2"다. 패자 열끗 0장 조건은 보통 붙이지 않는다.
- 현재 기본값은 "승자 5장 이상 + 패자 0장"이다. 이건 광박 구조에 맞춘 설계자 방식이라 일반 룰과 다르다.
- R07 선택지에 "승자 7장 이상, 패자 조건 없음"이 빠져 있다. 추가를 권한다.
- 기본값을 7장으로 올릴지도 사용자에게 묻는다(질문 2).
- 열끗 5장은 "열끗 점수 시작선"이라 거의 매 판 달성된다. 5장 기준이면 멍박이 지나치게 자주 터질 수 있다.

### 3-3. [중요] R02 고 가산 선택지의 정의가 모호함
- 5.3절 하단 주석은 "2점 고정"이라 하고, R02는 "3고부터 배수만"이라고 해서 3고 이상의 가산이 +2인지 +0인지 불분명하다.
- 선택지를 "(a) 고 횟수만큼 +n / (b) 1고 +1, 2고 +2, 3고 이상 가산은 +2에 고정 / (c) 가산 없음, 배수만"처럼 수치까지 명시한다.
- 기본값(+n, x2^(n-2))은 일반적으로 많이 쓰이는 방식 중 하나라 괜찮다. 3고부터 배수가 붙는 점도 맞다.
- 표의 "2고 +2점 (누적 총 +2)"도 "가산은 누적이 아니라 총량"이라고 한 줄 덧붙이면 오해가 줄어든다.

### 3-4. 국진 처리 시점
- R04는 "종료 정산 때 자동으로 유리한 쪽"인데, 5.2절의 7점 도달 판정은 매 턴 이뤄진다.
- 판 중 7점 판정, 상대 피 가져오기, 박 판정(국진이 열끗이냐 피냐)에서 국진을 어떻게 볼지 한 줄이 필요하다.
- 제안: 점수를 재계산할 때마다 해당 플레이어에게 유리한 쪽으로 자동 선택하고, 피 가져오기 대상에서는 항상 제외한다.

### 3-5. 자뻑·뻑·따닥 선택 규칙 보강
- 자뻑 상대 피 2장은 흔한 기준이다. 다만 지역별로 "자뻑 = 즉시 승리/고정 점수" 변형도 있다. R09에 그 선택지를 추가할 수 있다.
- 뻑을 낸 쪽의 페널티는 "없음"이 기본인데, 이는 일부 룰만 쓰는 단순화다. 개발에 영향 없으니 괜찮다. 다만 "단순화"라고 명시하면 좋다.
- 따닥은 "같은 월 4장을 H, D, 바닥 2장으로 전부 먹는 것"이라는 일반 정의와 맞다. 다만 "한 턴에 서로 다른 두 쌍을 먹는 것을 따닥이라 부르는" 지역이 있어서, 한 줄 주석("본 문서 정의 기준")을 권한다.
- 총통(10점 고정, 양쪽 총통이면 선 우선)과 R15(바닥 4장 재분배)는 일반적이다. 둘이 동시에 생길 때 처리 순서(총통 우선)만 한 줄 추가하면 된다.

### 3-6. 비광 포함 광 점수
- 3광 3점 / 비광 포함 3광 2점 / 4광 4점 / 5광 15점은 일반적인 값이다. 이대로 충분하다.
- 다만 R03의 "비광 포함 4광 3점"은 실제로 쓰는 지역을 확인하지 못했다. 선택지에서 빼거나 [확인 필요]를 유지한다.
- "비광 포함 3광 = 비광 + 다른 광 2장"이라는 정의 한 줄을 추가하면 구현이 쉬워진다.

### 3-7. 기타 정리 사항
- R17의 두 선택지("일반 피 우선 / 가치 낮은 순")가 사실상 같다. 선택지를 의미 있게 바꾸거나 R17을 삭제한다(예: 일반 피 우선 / 피 가져갈 때 상대가 고른다).
- 승리 기준 7점은 맞고에서 가장 널리 쓰이는 값이라 `[확인 필요]`를 약하게 바꿔도 된다.
- 카드 ID 규칙(`월-종류코드-순번`)과 JSON의 danGroups 표기("01-T")가 달라 보인다. ID 생성 규칙 한 줄이 필요하다(예: 같은 월·종류 안에서 0부터 매긴 인덱스).
- 3.2절 "더미가 비면 건너뛴다"는 2인 기준에서 도달할 수 없다(20턴 = 20장). 방어 코드로만 남겨 둔다.
- rules.md가 "balance.md"를 언급하지만 roadmap에는 해당 산출물이 없다. 5단계 산출물에 포함하는지 정리가 필요하다.

### 3-8. 문서 간 불일치 (spec <-> rules)
- spec 6절의 MVP 매직 카드 예시 4종(상대 패 보기 / 내 패 교환 / 점수 x2 / 바닥패 뽑아오기)과 rules 9절 후보 5종(엿보기 / 패 바꾸기 / 바닥 정리 / 되돌리기 / 방패)의 이름과 구성이 다르다.
- 특히 "점수 x2"와 "바닥패 뽑아오기"는 rules 후보에 없다. 다른 이름도 같은 효과인지 불분명하다.
- 5단계 game-designer가 확정하기 전에 한쪽 목록으로 통일하는 편이 좋다. 질문 4 참고.
- "점수 x2"류는 점수 공식 5.6을 건드리는 효과다. rules 9절 원칙("기본 점수 계산식을 직접 고치지 않는다")에 맞게 별도 배수 슬롯으로 분리해야 한다.

### 3-9. 사행성 관련 보강
- rules 머리말의 "칩, 코인, 랭킹 보상이 필요해지면 연출용 수치로만"은 spec의 "랭킹 제외, 현금성 보상 금지"와 결이 다르다. "칩·코인·랭킹은 MVP에 넣지 않는다"로 맞추는 것을 권한다.
- 5.6절 "패자는 최종 점수를 잃고 승자는 그만큼 얻는다"는 점수를 걸고 하는 판돈처럼 읽힐 수 있다. "이번 판 결과 점수로 표시한다. 판을 넘어 누적되는 보유 점수는 없다"로 바꾸는 것이 안전하다.
- 한국에서 고스톱은 웹보드게임 규제 대상이 되는 경우가 있다. 무료 · 무현금이어도 등급분류 필요 여부를 출시 범위(공개 범위)에 맞춰 확인해야 한다는 점을 spec 9절에 한 줄 추가하면 좋다. 내 지식이 정확하지 않을 수 있으니 확인 단계로 남긴다.

### 3-10. 스타일
- 문서가 개발자·기획자용 표 중심이라 일상 설명이 부족하다. 스타일 가이드("풀어서, 일상과 엮어 쉽게")에 맞추려면 spec 맨 위에 "사용자용 5줄 요약"(어떤 게임이고, 무엇이 정해졌고, 무엇을 골라야 하는지)을 두는 것을 권한다.
- 기술 문서인 rules.md는 현재 형태를 유지해도 괜찮다.

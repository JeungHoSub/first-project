# 클릭 선택지 규칙

사용자는 글로 답을 쓰지 않고 **클릭해서 고른다**. 질문, 추천안, 글 후보는 모두 아래 형식을 따른다.

## 1. 에이전트(서브에이전트)가 할 일
서브에이전트는 클릭 카드를 직접 띄울 수 없다. 대신 결과 보고 **맨 끝**에 아래 블록을 그대로 넣는다. 산출물 문서의 "사용자가 정할 것" 섹션에도 같은 형식을 쓴다.

```
### 선택 질문
Q1. [짧은 머리말(12자 이내)] 질문 문장? (중복선택: 아니오)
- A) 선택지 이름 (추천) — 고르면 어떻게 되는지 한 줄
- B) 선택지 이름 — 한 줄 설명
- C) 선택지 이름 — 한 줄 설명
```

- 질문 하나에 선택지는 **2~4개**이고, 추천안은 **맨 위**에 두고 이름 끝에 `(추천)`을 붙인다.
- "기타/직접 입력"은 넣지 않는다. 카드에 자동으로 붙는다.
- 질문 문장은 그것만 봐도 이해되게 쓴다. 앞 문맥이 카드에 보이지 않을 수 있다.
- 사용자가 고르지 않으면 어떤 선택지로 진행할지 `(미응답 시: A)`처럼 적어 둔다.
- 꼭 사용자가 정해야 하는 것만 묻는다. 관례나 기본값으로 정할 수 있는 것은 알아서 정하고 보고에만 적는다.

## 2. 글 후보도 선택지로
제목, 썸네일 문구, 첫 문장, 톤, 강의 구성, 게임 이름처럼 **취향이 갈리는 글**은 완성본 하나만 내지 않는다. 후보 2~4개를 만들어 같은 형식의 선택 질문으로 낸다.
- 각 선택지에 실제 문구를 그대로 넣는다. 예: `- A) "출근길 10분, 클로드 첫걸음" (추천) — 짧고 듣기 쉬움`
- 길어서 선택지에 다 안 들어가는 글(대본 전체 등)은 `outputs/`에 후보 파일을 남기고 선택지에는 파일명과 차이점만 적는다.

## 3. 메인 세션(총괄)이 할 일
- 에이전트 보고나 `log.md` "넘길 메모"에 `### 선택 질문` 블록이 있으면 **AskUserQuestion 도구로 클릭 카드를 띄운다**. 한 번에 최대 4개, 더 많으면 중요한 것부터 나눠서 묻는다.
- 선택지 순서와 `(추천)` 표시를 그대로 옮긴다.
- 사용자가 고른 답은 `brief.md`의 "결정됨"과 `log.md`에 기록하고, 다음 에이전트에게 넘긴다.
- 사용자가 응답하지 않은 질문은 `(미응답 시)` 안으로 진행하지 않는다. 대기 상태로 `log.md`에 남긴다.

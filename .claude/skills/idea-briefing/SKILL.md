# 수익화 아이디어 브리핑

## 공통 순서
1. `VISION.md`, `projects/money-ideas/brief.md`, `outputs/feedback.md`, `outputs/idea-pool.md`, 가장 최근 브리핑을 읽는다.
2. 회차별 조사(아래). 웹검색은 **5~8회 이내**.
3. `outputs/briefings/YYYY-MM-DD-{am|noon|pm}.md`로 저장, `idea-pool.md` 갱신, `log.md`에 한 줄 기록.
4. 커밋·푸시한다.
5. 사용자에게 보내는 마지막 메시지 = 브리핑 요약(휴대폰 화면 기준 15줄 이내) + 선택지 질문.

## 회차별 조사
| 회차 | 조사 | 소스 예시 |
|---|---|---|
| 아침 am | 새 아이디어 3개. 최소 1개는 "사람이 반복 수작업으로 하는 일 → 자동화 서비스" 유형 | 해외 소규모 SaaS·1인 사업 사례, 크몽·숨고·탈잉 수요, 네이버 트렌드, 정부 지원사업·공공데이터 |
| 점심 noon | 사용자가 고른 아이디어(없으면 점수 1위) 1개 심층: 경쟁 서비스·가격대·1~10 실행 단계 중 자동화 가능 단계·필요 비용 | 경쟁사 사이트, 가격표, 커뮤니티 불만글 |
| 저녁 pm | 오늘 정리, 아이디어 상태 변경 제안, 내일 방향 선택지, 피드백 질문 1~2개 | (조사 최소화) |

## 브리핑 파일 형식
```
# YYYY-MM-DD 아침 브리핑
## 한 줄 요약
## 아이디어 (또는 심층 조사 / 오늘 정리)
### 1. 이름 — 점수 NN/30
- 무엇: / 누가 돈을 내나: / 얼마: 
- 1~10 단계 중 자동화 가능: (예: 7/10, 사람 필요한 단계 적기)
- 근거: [출처](링크)
- 위험:
## 선택지
1. (추천) ...
2. ...
3. 다 별로 → 이유 알려주기
```

## 사용자가 답하면
- `feedback.md`에 기록, `idea-pool.md` 상태 반영.
- 두 번 이상 반복된 취향은 `style-guide` 스킬로 "학습된 선호"에 추가.
- 커밋·푸시.
